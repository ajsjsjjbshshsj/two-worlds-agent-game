## 审计与修复

| 存储 | 旧键 | 历史用途 |
| --- | --- | --- |
| `sessionStorage` | `twoworlds.session.token` | 旧匿名会话 Bearer 凭证 |
| `sessionStorage` | `twoworlds.recovery.pending` | 早期恢复密钥保存提醒标记 |
| `localStorage` | `twoworlds.recovery.pending.v1.<account_id>` | 按账号保存的恢复提醒元数据，曾包含账号标识、显示名、时间和状态 |

PR #33 后，旧值已无法用于 `/api/me` 或任何新版会话调用，但仍可能保留在曾运行旧版的浏览器中。`frontend/src/main.ts` 在挂载前调用 `clearLegacyIdentityStorage`，按两个精确会话键和旧版可写的账号键格式删除。它只遍历键名，保留同源其他数据与 `twoworlds.auth-context.*`，存储受限时继续启动并独立处理另一个存储。现行 HttpOnly Cookie 和原有邀请、命令、媒体 API 契约均保留。

同源 `localStorage` 的清理由首次加载触发，`sessionStorage` 按标签页清理。仍在运行旧版的标签页会在加载新版时清理，其他来源的数据由其自身处理。旧凭证被复制到其他位置、手工备份或浏览器扩展时，仍由服务器现行 Cookie 契约阻止其用于认证。

## 演示库与正式环境

本轮用全新临时 SQLite 文件和专用回环 MongoDB 实例中的随机空库，从重新注册开始。旧演示库和真实用户数据保留。开发邮件通过显式控制台发送，图像与音频使用项目测试发布工厂封存的素材，与正式发布库隔离。

真实本地启动读取包内默认 `/api/scripts` 仍为 `[]`。生产验收需要两部剧本的正式授权素材和发布、实际 HTTPS 与 SMTP 环境。T06.3.2/T06.3.3 是此轮账号前置，T07–T11 的房间、存档、投影和媒体能力是产品流程依赖。后续的 T12.2 客户端实时同步、T13 PWA/移动端及 T15–T16 部署和正式综合验收沿原路线继续。

| 项目 | 两种数据库复验结果 |
| --- | --- |
| 预置旧键再刷新，检查旧键和原有偏好键 | 四个测试旧键清除，偏好键保留，Cookie 流程正常 |

另在两种数据库上分别用同一浏览器上下文的两个标签页复验共用 Cookie。换号和登出传播到旧页面，延迟送达的房间与图片响应被丢弃。断网期间私人内容及命令入口暂停，网络恢复重试后可继续游戏。连续聚焦、可见和 `pageshow` 信号各合并成一次 `/api/me` 请求。关闭 BroadcastChannel 并屏蔽存储事件后，聚焦仍能重新确认账号，两轮均无页面异常。
