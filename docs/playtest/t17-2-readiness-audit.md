## 推荐的封闭试玩架构

建议后续实现一份独立的 `compose.playtest.yml` 和受审的试玩启动方式，复用现有镜像构建、Nginx 路由及应用服务。首批远程试玩采用隔离单机、一个 FastAPI 实例、启用认证的独立 MongoDB 和只读内容包。SQLite 用于本机合成演练。运行模式、存储、入口、密钥、外部调用与日志策略纳入启动前校验。现有安装包默认发布目录为空，当前 `twoworlds.server` CLI 没有独立内容目录变量，后续实现应通过现成应用工厂的 `publication_store` 注入或构建专用镜像显式选择受审的包。

~~~text
受邀设备 → 受控私网或 VPN → 独立试玩域名的 HTTPS/WSS 网关
                          ├→ Vue 静态服务
                          └→ FastAPI → 私有数据网 → 启用认证的试玩 MongoDB 与专用卷
                                     → 只读试玩内容包
~~~

- **入口**。优先使用组织者已有的受控私网或 VPN，只让获批设备到达网关。若需公网接入，经过单独批准后仅放行网关 TCP 443，并在 TLS 入口对全部路由实行邀请名单准入，优先使用稳定网段白名单或覆盖 WebSocket 的访问控制。链接本身不作为授权。HTTP 80 仅在已批准的验证或跳转方式确需时开放；可用 DNS 校验证书并保持 80 关闭。管理走独立已授权通道。后端、静态服务和数据库无公开端口，安全组覆盖 IPv4 与实际启用的 IPv6。接入与运营时检查从外部及未授权设备的访问结果。
- **TLS 与应用会话**。独立子域名承载 UI、API、受保护媒体和 WSS。使用真实设备信任的证书链，验证域名、有效期、部署和续期责任人。前端使用空的 `VITE_API_BASE_URL` 同源构建。后端显式设定精确 HTTPS Origin 与 `TWOWORLDS_COOKIE_SECURE=1`。保留 HttpOnly、SameSite=Lax、网关转发头覆盖和单一可信代理。若增加前置接入代理，应复验客户端地址、限频及可靠的 WSS Upgrade 和超时。
- **数据**。独立项目、网络、库名和卷、运行目录和测试账号。测试主机无正式数据库凭据，无通往正式数据网的接入。MongoDB 使用单独启用认证的实例、独立库和该库专用 `readWrite` 账号，数据端口仅在私网可达。首批允许单机故障导致场次暂停，后续再按实际恢复要求评估独立数据库主机或高可用。现有正式启动器强制 SMTP，Demo 启动器强制 SQLite。远程试玩的 MongoDB 与无邮件路径需要独立启动配置与验证。
- **身份与隐私**。首轮由组织者在受控环境预发每对两个专用别名账号，网页走正常登录。保留登记与验证码能力的合成预检，真实参与者入口对注册、验证码和密码重置写入关闭。后续可用仅后台执行的一次性工具，复用身份服务创建测试身份、不回传或记录创建会话，按需撤销。服务端选择拒绝任何邮件投递的实现，避免误开路由后向 stdout 输出验证码。现成启动器只有 Console 与 SMTP 选项，待在独立试玩入口组合应用工厂与拒绝投递适配器。若把参与者自助注册纳入目标，需要另行设计并复验受控验证码交付。
- **运行与清理**。后端固定 `TWOWORLDS_AI_MODE=demo`，无 Provider 配置或 API Key，禁用外部追踪和邮件出站。每批注入独立的强随机验证密钥，凭据和 TLS 私钥仅以受控运行配置提供。验证路由、请求头、正文、Cookie、验证消息、邀请和私聊均无原值进入日志、追踪、前端产物及 CI。建立容量上限、失败计数和日志轮换。结束先关入口并撤销会话，然后按已经核对的试玩环境清单清理库或卷、账号、日志、网页测试配置、快照和临时发布目录，停用入口凭据及 DNS。保留经允许的脱敏研究记录，按 T17.1 最长 30 天到期或依撤回请求提前清理。保留过程记录用编号和结果，不保存密钥原值。

### 服务器规格与成本假设

| 方案 | vCPU / 内存 / 磁盘 | 规划用途 |
| --- | --- | --- |
| 最低可行 | 2 vCPU / 4 GiB / 40 GiB 加密 SSD | Linux x86_64，使用预构建镜像，可作本机 SQLite 原型和受控低并发验证的下限。若同机运行 MongoDB，先用合成并发验证内存、磁盘，记录限制和失败，不据此承诺真人场次容量 |
| 推荐 | 4 vCPU / 8 GiB / 60 GiB 起的加密 SSD | 推荐用于同机独立 MongoDB 的首批远程试玩。给数据卷、镜像回退、内容包、系统更新和故障排查留余量。数据库若独立部署到第二台主机，另算实例、磁盘和流量 |
| 扩展 | 先纵向扩大，测出瓶颈后再分离 | 前端静态内容可独立扩展，受保护媒体保留授权。跨实例前先验证 MongoDB 认证、共享状态与存档一致性、并发限频及 WS 恢复，再评估负载均衡和高可用 |

估算场景按一台 Linux 按需机运行 14 天、336 实例小时、60 GiB 系统及数据盘、20 GB 外网出站和按需一个公网 IPv4（最多 336 小时）。假设无负载均衡、托管数据库、真实 AI 和 SMTP。按月计盘的场景近似 28 GiB·月，供应商按实际计量。总价由该地域实例单价乘实例小时、磁盘单价乘计费容量、IP 或带宽/出站计费、域名与 DNS、证书（若付费）、必要备份与快照、接入网络或日志费用、税费组成。实例停止后若仍保留磁盘、快照或分配的 IP，按供应商规则继续核算。注册域名、网络和备份若已纳入现有服务则按实际增量费用登记。该情景是询价输入，尚无地区实例报价、真实流量或容量测量。

- [ ] 内容负责人签核用途范围与对参与者的原型说明。记录发布版本、素材摘要和来源，确认两个剧本出现在实际测试书架，并由两人分别控制角色通关。
- [ ] 组织者批准独立测试入口、数据地域与访问方式。核对独立数据库及最小权限，验证公开端口、未获准设备与账号的失败路径，并核实没有网络路径或凭据可连接生产数据库。
- [ ] 实测真实受信证书、同源 HTTPS/WSS、单一精确 Origin、安全 Cookie、代理身份、敏感路由和内部探针的公开阻断。检查日志、前端产物与错误路径中无凭据、验证码、Cookie、邀请链接、密钥或私聊原值。
- [ ] 固定 Demo，检查运行态配置与网络出站。准备每对两个专用账号，明确预发账号和注册预检的边界。获得双方同意后才开始记录。
- [ ] 待开测入口完成双端和第三身份隔离、刷新、断网、重启、切档与登出清理的合成演练。在拟使用的设备与网络上预检。手机探索场取决于真机结果。
- [ ] 复验独立实例撤场。确认入口关闭，测试账号及会话撤销，卷或库、日志、临时发布包、证书部署副本与已登记快照完成清理。观察资料依约留存并复核到期删除责任。不合格项按 [P0–P3 升级](issue-template.md)，疑似隐私泄露时立即暂停。

## 需要用户决定

1. 只做获批占位素材的流程原型，还是等正式素材和审核齐备后再开测。
2. 参与者主要在哪些地区和网络，数据允许存放何处，是否已有可复用的域名、私网和云账户。选择阿里云或 AWS、首选地域与可接受的预算上限。
3. 首轮是否固定桌面与预发账号。若要纳入手机或参与者注册，确定额外验收范围与负责人。
4. 是否批准在下一环节实现独立 Compose、内容加载、账号准备及撤场流程。明确谁签核内容、谁验证入口、谁负责清理。T17.1 的主持和招募材料在这些条件满足后再用于真实场次。
