# TwoWorlds · 试玩主持人手册

## 开场前

- 在独立测试实例使用当次构建与两个可读的 1.0.0 剧本。确认两端可以访问同一入口，书架显示《跨时灯塔》和《末班星轨》，两枚独立账号可以登录、建房、邀请、确认 B 加入、打开同一档、提交行动和重新进入。用预检账号验证，清理预检房间并为正式场次换全新的独立账号与空房间。
- 事先给每对准备两个仅用于测试的邮箱别名和独立凭据。正常场次用预先注册的账号在 UI 登录。另选经过同意的场次走注册步骤时，可用专用别名，由主持人从隔离控制台取对应验证码，仅向本人转达，不发真实邮件；将注册耗时单独注明。
- 两台电脑使用 Chrome 或 Edge 为首选。同机两人轮流或并排操作时，用两个独立浏览器配置，并注明共用设备。手机只在相同机型、系统和浏览器的现场预检通过后安排；记下软键盘、音频、前后台恢复的异常及是否换回桌面。
- 让参与者使用已有通话方式或当面讨论。确认组织者在两人同意的情况下可以观察所需操作。记录行为和次数，避开登录、邀请、隐私页面和通话内容。关闭会议自动录制或自动转写。
- 任何测试书架为空、入口不可达、素材授权不清、外部 AI 仍可启用或测试库指向正式库的情况都先停。按[方案的开测条件](t17-1-playtest-plan.md#开测条件)和[隐私与同意](privacy-and-consent.md)预检。

### 仅本机的合成环境核对

T16 的现成夹具可临时封存两个剧本并启动同源页面，使用测试 PNG/WAV、临时 SQLite 和控制台验证码。它只绑定本机，可用于主持人在招募前用合成身份演练。实际发给参与者的入口和素材须另经确认。默认的正式内容目录为空，不能把已有启动命令直接当作可试玩的公开入口。

从仓库根目录安装锁定依赖，再在前端目录打开本机核对环境。脚本第一行输出入口，第二行仅供主持人定位临时验证码日志。按回车关闭环境并清理临时目录。测试日志含短期验证码，只在本机受控终端查看。

~~~bash
(cd backend && uv sync --locked --group dev)
(cd frontend && npm ci)
cd frontend
TWOWORLDS_AI_MODE=demo VITE_API_BASE_URL='' PYTHONPATH="$PWD/e2e" \
  ../backend/.venv/bin/python -c '
from t16_dual_browser import real_stack
with real_stack("sqlite") as stack:
    print(stack["base"], flush=True)
    print(stack["folder"] / "console.log", flush=True)
    input("Press Enter to stop the local rehearsal. ")
'
~~~

## 开场和观察

可对两人这样说明：

> 我们在测试这个游戏。想知道哪些地方好懂、哪些地方会卡住，你们的感受可以不同。请按自己的习惯操作和交流。有不舒服的地方可以跳过、暂停或退出。我们会按之前说明记录用时和遇到的情况，不录音录像。你们各自确认愿意开始后，我再开始计时。

1. 用两人各自确认的记录开启计时，照[方案](t17-1-playtest-plan.md)推进。说明测试账号和操作指南在哪，避免代点或透露题解。若首次点击没成功，先留意当事人接下来怎么做。记录是 A 还是 B、看到的界面、本人是否主动找到下一步。
2. 使用[观察表](observation-sheet.md)。记录双方游戏相关的发言往返次数、各自确认成功的动作、第一次有效合作、等待、主动检查物件、卡关、技术故障和继续意愿。禁止照抄讨论原句。非游戏话题无需记录。
3. 玩家主动求助或同一障碍达到两分钟时，可以先问「你现在想做什么？」或「你们各自已经看到什么？」再按需要指出界面位置或协助网络、登录等故障。每次介入登记时间、类型和结果。保持两人的讨论空间，让玩家自己选择操作。
4. 如遇疑似串档、私密泄露等 P0，停止相关场次与待开始场次，按[问题处理](issue-template.md)隔离。P1 先记录和协助安全退出；一方退出时停止双人计时，不用主持人接替。
5. 结束后分别问「刚才这段游戏里两个人各自做了什么？」和「你怎样知道两边需要配合？」给两人独立回答的机会。允许回答不清楚或不答，按[指标](t17-1-playtest-plan.md#指标和决策)编码。可以再问哪里顺畅、哪里烦躁、是否想再约。先记自由反馈，保持中性语气。
6. 请两人[各自填写问卷](post-playtest-survey.md)，各自决定是否愿意继续星轨。记录实际是否开玩，以及退出或未开始的原因（自愿填写）。按[隐私流程](privacy-and-consent.md)处理退出、清理和留存。

## 收场核对

- 核对两人登出，再关闭本次环境；保持观察与问题表仅含编号和必要记录。
- 上报角色失衡、规则误解、流程阻断和意愿缺失；区分观察、推测和未知。若同一故障重复，按问题编号关联场次，不修改原始计数。
- 下一场使用不同账号、不同房间及独立浏览器配置。准备交接时仅共享去身份汇总和允许共享的脱敏问题。
