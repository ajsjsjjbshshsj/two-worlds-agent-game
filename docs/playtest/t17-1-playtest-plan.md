# T17.1 · 真实用户试玩方案

计划邀请 **3～5 对情侣，共 6～10 位成年人**。每对选一个时间一起参加，游戏经验不限。每套剧本目标约 1 小时（50–70 分钟）。每对只测试一篇；若两人都愿意继续，第二篇另安排完整 50–70 分钟场次，不压缩或强迫连续试玩。本阶段交付材料，试玩结果待实际开测后填写。

## 要验证什么

| 目标 | 要观察的问题 |
| --- | --- |
| 双人协作 | 是否需要交换信息才能推进；两角色是否都有实际贡献；谁在等、等多久；是否会主动讨论；单人是否有机会包办进度 |
| 剧情与谜题 | 两人能否复述当前目标；是否关心故事和结局；难度是否合理；哪里不知道下一步该做什么 |
| 游戏时长 | 实际耗时是否接近 50–70 分钟；章节节奏是否自然；是否愿意投入约一小时；暂停和回来继续是否顺畅 |
| 产品价值 | 是否享受合作、愿意约玩第二篇或推荐；是否有付费意愿；拒绝、犹豫和中止的原因是什么 |

## 开测条件

1. 使用独立的封闭测试实例，保存到可销毁的测试库或临时 SQLite。账号、房间、邀请码、日志和存档均独立于正式用户。按[主持人手册](moderator-guide.md)逐项预检，按[隐私与同意](privacy-and-consent.md)执行。
2. 首轮优先使用两台电脑、各自的 Chrome 或 Edge、稳定网络。需要远程沟通时由参与者使用自己熟悉的通话工具。也可现场口头交流。具体浏览器版本和设备组合先由主持人走一遍。手机可在实际设备同路径预检后单独登记为探索场，另记录设备故障和切回桌面的情况。
3. 固定记录构建提交、剧本版本和素材类型。两篇均为 1.0.0，当前 1.0.0 内容元数据的预估时长仍为 15 分钟，属于旧版本声明；本轮约 1 小时是新设计目标，须在新内容版本发布后更新元数据。当前正式发布目录为空，已验证的 T16 环境使用封存的合成占位素材。正式组织试玩前，需要准备经负责人确认可用于封闭原型测试的内容与素材，并确认两个故事在测试书架可进入。空书架、素材没有使用许可或测试入口未经确认时，延期。设备证据和已知问题见 [T16 报告](../reports/acceptance.md)、[设备记录](../reports/devices.md)和[限制清单](../reports/known-limitations.md)。
4. 只使用 Demo。后端示例 NPC 返回固定通用建议，当前游戏页未提供 NPC 对话入口；网页内语音也未启用。机关、进度与结局由现有游戏规则决定。首轮评估只据此评价协作体验，问卷不要求评估 AI 对话质量。

## 试玩 A · 跨时灯塔

一人在旧灯塔照料发射装置和机械，另一人在未来观测站识别反馈并管理能源。用这篇观察两人是否能交换彼此独有的信息，通过各自操作推进并共同决定结局。主持人保留实际卡点与失败，沿用当前谜题和规则。

| 环节 | 计划 | 操作 |
| --- | ---: | --- |
| 说明和同意 | 3 分钟 | 分别确认两人同意；发放各自测试账号；说明私密信息与退出方式 |
| 登录、建房、邀请 | 3 分钟 | A 登录创建房间，B 打开 A 的邀请并确认加入；两人进书架 |
| 共同游玩 | 50–70 分钟 | 双方进入灯塔，从同一存档读取自己的信息、讨论和提交行动，完成六章叙事体验或主动停止 |
| 自由反馈 | 4 分钟 | 让两人各说一次最顺利和最困难的环节；主持人征询是否想继续 |
| 独立问卷 | 5 分钟 | A、B 分别填写，可跳过问题或只提交退出原因 |

首次计时从打开测试入口开始。双方首次进入同一剧本时开始游戏计时；以共同结局、主动停止或观察窗结束为终点。默认游戏观察窗 70 分钟；若双方都愿意可延长一次，最多 15 分钟。主指标按实际耗时统计，同时记录是否在 50–70 分钟目标范围内完成。到观察窗仍在玩记为「未完成—观察窗结束」，不代为通关。另记技术等待、主动暂停与原因；超时未能入场仍记录为入场未完成。进度恢复和页面切换可在自然需要时观察。

## 试玩 B · 末班星轨

两人分别独立表达意愿。两人都愿意且时间允许时，从同一房间的书架进入《末班星轨》；否则可单独约一个自愿时段。新场若已清理上一轮实例，用新的独立测试账号及新档开始。选择愿意、实际开始、完成或退出分别记录，拒绝时可自愿说明原因。

站台端和列车端要协作勘测、分配能源并交换信号。主持人观察玩家感受到的玩法差异、私有信息是否被用于协作、角色是否仍都参与。结束后由两人分别补答[问卷的第二篇问题](post-playtest-survey.md#选填第二篇)。该段时长与行为单独统计。

## 指标和决策

先冻结指标规则再开测。报告总人数及实际分子、分母、缺失、退出和设备差异。下表的「已开始对数」指完成同意并打开测试入口的对数，保留在同意范围内可统计的技术中断和退出；撤回数据时从可用数据中移除并注明可用样本变动。无数据或分母为零时标记「无法判断」。

| 指标 | 初步阈值 | 计数方法 |
| --- | ---: | --- |
| 成功进入首篇 | ≥90% | 双方进入同一灯塔存档的对数 ÷ 已开始对数 |
| 完成基础流程 | ≥80% | 在观察窗内由两人操作至首篇共同结局的对数 ÷ 已开始对数；另列 50–70 分钟内完成以及有主持提示的对数 |
| 双方有参与感 | ≥80% | 问卷 P1 双方均给 4～5 分的对数 ÷ 两人均有效回答 P1 的对数；另列只有一人答或选跳过的对数及实际操作差异 |
| 双方理解基本规则 | ≥80% | 两人均能独立说出「各自信息或操作不同」以及「一方行动会影响对方，两人要配合推进」的对数 ÷ 有两人有效复述的对数；主持人先问后评分 |
| 愿意尝试第二篇 | ≥60% | 独立问卷 V1 给 4～5 分的人数 ÷ 有效回答 V1 的人数；另报两人都愿意的对数和实际开始第二篇的对数 |
| 严重数据隔离问题 | 0 | P0 事件数；任何疑似泄露已触发暂停时，在排除前禁止给出通过结论 |

每篇另报实际时间、第一次有效合作时间、卡关、主持介入、技术故障、临时中断和退出、各角色行动和沟通次数。记录暂停、想继续以及碍于时间或设备无法继续的区别。报告写出原始比值，例如 4/5 对入场为 80%，低于 90% 阈值。完整记录口径见[观察表](observation-sheet.md)。

P0 按[问题处理流程](issue-template.md)立即停止。P1、关键指标未达标或样本缺失过多时，结论可以是「体验不合格」「先修复再测」或「证据不足」。达到阈值只支持本批样本的下一步决策。付费回答是意愿，试玩无付款环节。记录本轮外部模型调用量为 0 的配置依据，实测开销待试玩后按发生项登记。
