# 01 · 产品需求与用户流程

> v0.2 设计提案 · 2026-10-26。本文描述待实现行为，当前没有可运行产品。

## 1. 产品目标与使用场景

**目标用户：** 想通过共同活动增加交流的异地情侣；双人朋友可以使用相同机制，首版不要求提供真实关系证明或情侣隐私。

**典型场景：** 晚上两人分别拿手机或电脑，打开链接，选一个短剧本，用约 10–20 分钟完成一次合作冒险，也可以中途退出，第二天继续。

**产品价值：** 给两个人一个必须交流、试验和共同决定的互动情境。AI 提供角色表达与氛围；可解的谜题、可靠的进度和稳定的同步构成基础。

| 设计问题 | 本次选择 | 可检查的结果 |
| --- | --- | --- |
| 单故事还是平台 | 多剧本共用引擎 | 切换两个剧本不串数据 |
| 直接答案交换还是合作探索 | 非对称操作 + 可观察因果 | A 的动作改变 B 可用内容，B 的动作也反馈 A |
| 自由生成还是固定内容 | 审核过的故事骨架与规则 + AI 表达 | 模型断开仍可通关 |
| 三端分别开发还是网页共用 | Vue 3 + TypeScript + PWA | 同一账号换设备继续 |
| 工程原型还是公开商业产品 | 先交付可验证原型，再做试用与商业准备 | 报告区分可运行、已验证和未公开部署 |

## 2. 版本边界

| 能力 | 首版 v0.2 | 后续 |
| --- | --- | --- |
| 个人身份 | 匿名身份、恢复密钥、期限会话、登出 | 邮箱/第三方登录、密钥轮换与迁移 |
| 双人关系 | 一房间两个固定席位；可在本人房间列表选择 | 解绑、换搭档、邀请审批与关系管理 |
| 剧本 | 两套不同机制的原创单章故事 | 更多题材、长篇章节、作者工具 |
| 存档 | 每房间每剧本一个，完成可回看 | 多槽、重开、归档、迁移 |
| 沟通 | 公共线索栏；NPC 私聊；可同时使用外部电话 | 站内玩家聊天、实时语音 |
| 纪念内容 | 程序根据共同事件生成文本回顾 | 自愿分享的回答、插画卡片、纪念册 |
| 商业化 | 记录经同意的试用反馈与使用成本 | 付费故事包、支付、退款及正式运营 |

首版不提供房间满员后的角色互换或移除搭档，避免存档归属歧义。用户可以登出；对外试用前提供明确的数据删除申请渠道，正式公开版本再实现经过双方数据边界设计的自助删除与关系退出。

## 4. 环节一：首次进入与创建身份

**用户做什么：** 输入显示名，创建身份，按提示保存恢复密钥。

**页面展示：** 产品一句话说明、“创建身份”“恢复身份”两个入口；创建后展示一次恢复密钥、复制按钮、保存提示与“我已保存，继续”。不要把确认保存设计成已写入系统剪贴板之外的自动备份承诺。

**系统做什么：** 服务端生成身份、256 位随机恢复密钥和独立短期会话，只保存凭证摘要；响应禁止缓存。显示名只作展示，不参与认证。

**异常：** 名称为空或超长就地提示；重复点击防抖；限频显示稍后再试；请求结果未知时提示身份可能已创建，不自动无限重复创建。响应丢失且用户没有拿到恢复密钥的匿名身份不承诺找回。

**最终结果：** 用户拥有自己的身份与会话，进入双人空间。首版不收集手机号、真实生日或关系经历。

## 5. 环节二：恢复与设备切换

**用户做什么：** 在另一设备输入恢复密钥。

**系统做什么：** 用恢复摘要查找身份并签发新会话；恢复密钥不直接用于日常 API。当前建议会话有效期 7 天，最多保留 5 个活跃会话，超出则撤销最旧一个；这些为可配置默认值。

**页面展示：** 恢复中、密钥错误、请求过多、恢复成功。成功后列出本人房间和各档进度。

**多设备行为：** 同一账号可以多端查看和提交，统一以服务器版本解决竞争；首版不增加“唯一活动控制端”。这与历史聊天中的单控制端建议不同，是为了减少控制权租约复杂度；保留未来扩展边界。

**最终结果：** 不创建新身份、不复制存档，不因换设备而丢失进度。没有期限无限续用的凭证。

## 6. 环节三：建立双人空间

| 步骤 | 用户行为 | 系统行为 | 页面结果 |
| --- | --- | --- | --- |
| 创建 | 甲点击创建房间 | 绑定甲为 A，生成有效 24 小时的高强度邀请 | 等待搭档，显示角色、邀请及到期时间 |
| 邀请 | 甲复制链接发给乙 | 链接只含邀请能力，不含甲的会话 | 乙进入接受页 |
| 登录 | 乙创建或恢复自己的身份 | 认证后才允许加入 | 乙知道自己即将成为 B |
| 加入 | 乙接受邀请 | CAS 占用空 B 位，满员时令邀请失效 | 双方看到已满员的房间 |
| 重试 | 乙重复原加入操作 | 对已是成员的身份返回原房间 | 不重复占位 |
| 更新邀请 | 甲在未满员时重新生成 | 旧凭证失效，新凭证重新计时 | 页面显示新邀请 |

邀请建议使用 URL fragment 承载，前端读入内存后立即清理地址，并通过 POST 请求体提交，避免进入访问日志和 Referer。没有账号时可在当前页面完成身份创建；刷新丢失邀请后需要重新打开原链接。

房间未满员时允许阅读公开开场与角色介绍，全部改变游戏事实的操作和 NPC 会话待双方就位后开启。房间成员只表示加入关系，不表示当前在线。

## 7. 环节四：剧本库与选择

每张卡片展示：名称、封面或占位插画、简介、题材、预计时长、角色分工、难度、未开始/进行中/已完成、继续按钮。

**用户选择：** 打开一个剧本；服务端按 `pair_id + script_id` 返回现有存档或创建新档，绑定不可变 `script_version`。

**两人打开不同剧本：** 允许浏览各自的档，页面始终显示当前剧本。伙伴是否正在同档游玩必须依据连接状态单独判断；首版只显示“已加入房间”，不伪装实时在线。

**切换规则：** 有结果未知的写操作时先确认或重试，确认后再切换。普通读取和旧 WS 可取消；网络请求取消不等于服务器已撤销写入。

**最终结果：** 用户明确知道自己在玩哪一档，从对应进度进入故事。

## 8. 环节五：进入游戏与探索

| 区域 | 展示内容 | 交互 |
| --- | --- | --- |
| 顶部 | 剧本、角色、章节、同步状态、返回入口 | 切换分区和返回书架 |
| 共享故事 | 当前章节事实、公共事件、当前合作任务 | 阅读与回顾 |
| 我的世界 | 当前角色场景、可观察物、个人设备状态 | 检查物件、调节设备、探索位置 |
| 我的线索 | 已发现信息及公开状态 | 分享可公开线索 |
| 操作区 | 服务器给出的可用动作和参数 | 选择、确认、机关操作 |
| NPC | 当前角色私聊、示例/真实/降级标识 | 提问 |
| 合作状态 | 等待什么变化、伙伴是否提交结局选择 | 共同决策 |

单纯切换面板、展开已发现线索不产生写操作。首次检查获得线索、调节设备、选择路线等会改变状态，需要服务端确认。

每个关键反馈同时回答三件事：我做了什么、我现在观察到了什么、下一步可以尝试什么。不要直接暴露对方的私有视图，也不把服务器完整规则表放进前端。

## 9. 环节六：沟通、试验与合作

用户可以通过外部电话讨论，也可在平台公开线索。分享是由服务器从已发现线索中生成公开条目，禁止客户端任意把未解锁的 clue ID 标成公开。

首次错误尝试应提供可理解的反馈，例如“对方观测台尚未收到稳定光束”。规则不满足时不改变存档；合法试验即使没有推进章节，也可以改变设备、观察结果和公共事件。

首版不设置现实倒计时、永久死亡、随机必败或无法撤销的早期错误。调节和路线试验可恢复，关键结局选择在双方一致前可修改。

**最终结果：** 玩家通过观察另一人的反馈推断关系，双方都执行必要操作，完成可验证的合作链。

## 10. 环节七：NPC 与提示

NPC 是氛围与交流辅助；提示采用三级：提醒观察对象、提醒协作方向、提供当前已知事实下的明确操作建议。级别和模板由规则定义，AI 只润色允许提供的文本。

AI 输入仅含当前角色投影、公开设定与本人最近对话；模型不拥有全档读取和状态修改工具。输出不可信，不能产生权威道具、密码或完成标志。

无模型配置显示“示例回复”；调用失败显示“服务暂不可用，已使用示例回复”。生成中不锁住另一人的游戏操作；生成结束时若版本已变化，拒绝陈旧写入，用户重新确认后再问，禁止自动重复付费调用。

## 11. 环节八：暂停、断线与恢复

| 场景 | 页面行为 | 系统行为 |
| --- | --- | --- |
| 服务器已确认操作 | 显示已保存 | 状态与回执已原子写入 |
| 提交中 | 显示确认中，防止重复点击 | 保留原请求 ID |
| 响应丢失 | 显示操作结果待确认 | 使用同一 ID 与相同内容重试 |
| 版本冲突 | 保留输入、更新画面、请求重新确认 | 返回 409 与稳定错误码 |
| 离线 | 显示连接中断，暂停新操作 | 退避重连、重新鉴权、拉取完整快照 |
| 切后台回来 | 显示恢复中 | 主动刷新会话/连接与快照 |
| 恢复密钥/会话失效 | 显示恢复身份入口 | 停止读取与提交，WS 关闭 |
| 数据库故障 | 显示保存失败、输入保留 | 不返回成功，不转内存临时存档 |

客户端持久化待确认请求时只保存当前账号、存档 ID、请求 ID、预期版本及普通机关参数。NPC 问题正文默认只留内存；刷新丢失时可以按回执查询该 ID 是否成功，不自动重放私聊内容。登出后清理本机待确认记录。

## 12. 环节九：共同结局与回顾

两人各自选择结局方向；不一致时显示“等待共同决定”，各自可改选。最后一次合法提交使双方一致时，由规则引擎生成结局 ID，原子完成一次结算。

完成页展示剧本结局、共同里程碑、两人各自贡献与返回书架。回顾只引用公开或已明确共享的事实，绝不展示伙伴私聊或隐藏线索。

首版允许回看完成档，不提供重置。NPC 在完成后可继续围绕已完成事实对话，仍受额度与权限约束，不能改写结局。

## 13. 可用性与界面规则

- 中文界面，夜蓝、雾蓝、暖金为方向；场景与角色区分有文字辅助，不仅靠颜色。
- 手机采用故事/我的世界/线索/NPC 分区；桌面并列共享故事与个人面板。
- 触控目标建议至少 44×44 CSS 像素，输入框避免被软键盘完全遮住，支持键盘与焦点提示。
- 首屏加载、空房间、空存档、错误、重连、AI 生成均有明确状态。
- 遵循减少动态效果偏好；没有音频自动播放或首版麦克风授权。
- UI 使用“进度已更新”“请确认后再试”，不暴露 CAS、LangGraph 等实现词。
