# T17.3.2 · 双人剧情与交互热点纸面原型

2026-11-28 · 评审稿 · 基线 `codex/bootstrap@b77a4e9`，包含 PR #60。本文是主持人、内容、美术与程序的工作稿，含解法。发给玩家时只使用本人卡片和已确认公开卡片。

## 1. 如何阅读和演练

每篇六个叙事章，计划合计 60 分钟，目标中位数 55–65 分钟，常见 50–70 分钟。无强制倒计时。短演出可跳过，重复点击、延迟、技术等待和暂停另记。现有两个 1.0.0 的元数据仍为 15 分钟、各有四个规则场景。两条现有轨迹足以验证双向协作和四个结局，约一小时的有效体验有赖下文的新增证据链，时长仍待走读和试玩。

- **现有**指 JSON、规则、权限、快照或已投影媒体可提供的锚点。事件表标 **A**。原型中相应的新对白、插图和坐标仍是制作说明。
- **待开发**指 1.0.0 不具备的确定性证据、命令、章节、提示调度或投影。事件表标 **B**。纸面由主持人执行约定，实际版本需实现后验收。
- **可选 AI**只复述已授权文本，事件表标 **C**。内容与条件均有作者版本，关掉模型也能完成。两个玩家的角色仍记为 A、B。

**走读方法。** 给两名玩家分别发本章的 A 卡、B 卡，各自看图和获准信息。主持人单独保留条件、答案和事件表，玩家口头交流，主动选「分享」才发公共线索。每个操作先说意图并明确确认参数，主持人核对权限、可见条件和当前状态，然后只给各角色发对应反馈。按确认顺序标记纸面快照和一次性演出。任意章中可中途停下，从最近的确认节点恢复，保留有效证据，重新计算临时装置条件。18 岁以上参与者真实试玩另按现有计划授权。本轮未进行真人计时。

**代码核对。** [两篇规则内容](../../backend/src/twoworlds/content/scripts)定义行动、场景和既有素材。[通用引擎](../../backend/src/twoworlds/domain/engine.py)验证角色及动作，专属[灯塔规则](../../backend/src/twoworlds/domain/mechanics/lighthouse.py)与[星轨规则](../../backend/src/twoworlds/domain/mechanics/starline.py)维护世界约束。[个人投影](../../backend/src/twoworlds/domain/projection.py)、[视觉投影](../../backend/src/twoworlds/domain/visuals.py)和[公共回顾](../../backend/src/twoworlds/domain/recap.py)决定不同角色能看到什么。已确认的状态通过 HTTP/WS 到 [Game Store](../../frontend/src/stores/game.ts)，[Game.vue](../../frontend/src/views/Game.vue) 现为场景与面板并列，[SceneRenderer.vue](../../frontend/src/components/game/SceneRenderer.vue) 已接授权媒体和 SVG 原型，热点只能定位设备面板。[ActionPanel.vue](../../frontend/src/components/game/ActionPanel.vue) 依据快照列出操作，[Device.vue](../../frontend/src/components/game/Device.vue) 展示本角色确认读数。已具备[相邻快照演出](../../frontend/src/services/causal-performance.ts)与[音频、字幕和恢复控制](../../frontend/src/services/audio.ts)。[SaveService](../../backend/src/twoworlds/application/saves.py)有角色私密 `talk` 路径，[Demo NPC](../../backend/src/twoworlds/application/dialogue.py)只返回固定回复。当前前端丢弃对话内容，剧本内的提示条目也没有面向玩家的提示入口。

## 2. 《跨时灯塔》六章

守灯人 A 在旧塔听见求援，观测者 B 在未来台发现同一次风暴的旧记录。两人先确认是谁在发信，再验证另一端现在有人值班，继而让供电、走时与航路共同恢复。A 的私人夹页始终留在本人侧，B 的回应只根据公共事实和最终结局生成作者台词。

### L01 · 风暴来信（8 分钟）

**事件。** 风雨盖住海面的求援音，未来观测台却收到一份没有抵岸记录的旧呼叫。两人要辨别正在讨论的是同一艘船，还是误认了定期演习。

| 角色 | 场景、可观察物和本人动作 |
| --- | --- |
| A | 暖灯下的旧塔楼梯与窗，左前景维护册，右窗有掠过海雾的灯。查维护册取得现有 `a_maintenance_log`。新卡为值班转录片，记录「三短、停顿、一长」及「来自海面」。不印航道或滤镜答案 |
| B | 裂窗冷光、海图及左右两格索引柜，远端风浪照在玻璃。查航道图取得现有 `b_sea_chart`。新卡中，例行试灯有同一节拍但来源为陆侧测试机。海上呼叫与节拍、来源同时相符，还缺可信的抵岸结果 |

**交流与解法。** A 报来源与节拍，B 用索引排除同节拍的试灯。未来 A 标记「海面呼叫」，B 提交「海上求援档」核对。两者都正确才显示「同一份求援已对上」。这一结论只确认讨论对象，仍保留录音假设。错把例行记录选成求援时，A 留当前观察，B 获得「来源未匹配」的反馈，可改自己的归类。

**世界与结束。** 本人材料的翻页与回放只影响读屏。双方完成规则检查是现有锚点，未来再以联合配对的 `mayday_matched` 结束 L01、开启 L02，底层仍为 `calibration`。现有规则没有独立 L01 结束。片头用风声和短喊衔接，潮汐记录员在两份记录打开后提醒「先确认你们说的是同一份求援」。提示依次标出窗与索引、建议口头核对来源、指出同节拍仍需排除陆侧记录。

### L02 · 第一次试灯（10 分钟）

**事件。** 两人知道求援记录相同，仍需确认放在哪里的光能成为可读信号。

| 角色 | 场景、可观察物和本人动作 |
| --- | --- |
| A | 发射架与黄铜刻度占近景，窗只有散光。维护册授予四档、两种光型及识别建议。通过 `set_emitter` 设置角度和光型。未来可在定角度下标记改变光型的对照起点 |
| B | 冷光观测台，海图在左，滤镜和光斑在右。通过 `set_filter` 调透射。只有读图且脉冲经琥珀时才看见真实落点。未来可在等角度的两次观测中选择「清晰度改变」证据 |

**交流与解法。** 先在约定角度看散光，再试一次可区分变量的对照。例如 A 把连续光切为脉冲，B 仍用透明片，散光继续。B 换琥珀片，A 保持角度，B 看见清晰但可能错误的落点。B 先确认滤镜作用，再报实际地标与目标差别，请 A 调角。两人已经在上一环节观察过有效对照时可直接沿用已确认样本。无需试遍选项。B 一时看不出差异可向 A 请求单变量测试。即使知道参数，光路控制和获得观测仍分别属于两人。

**世界与结束。** 现有两组装置、B 清晰度及落点投影会变化。未来记录对照必须来自同角度且光型或滤镜发生真实变化的已确认样本，双方各标记自己的改变或读数，产生 `beam_contrast_confirmed`。达到实际锁定配置（90°、脉冲、琥珀）后开启 L03。L02 未调用 `lock_signal`，现有底层仍停在 `calibration`。聚焦只在 B 的确认画面展开，不把原始落点送到 A。短句「把刚刚改变的设置告诉另一端」。提示从找光学控制到只改单一变量，再从本人对照指出下一步。

### L03 · 信号锁定（10 分钟）

**事件。** 观测者提出主动验证。能读懂对方的新请求并回信，才证明看到的是当前联动。两端此时没有读到彼此私人档案。

| 角色 | 场景、可观察物和本人动作 |
| --- | --- |
| A | 暖色发射架侧面，窗上可见新增双色形状回执灯，私人维护带说明「按相反顺序回送两拍」。未来从回信盘提交两拍逆序。只看服务器获准的当前请求与本人回应 |
| B | 冷色台面，波形在景深中部。未来从挑战键选择一个新的两拍组合，例「短、长」，看到回读和请求标识。根据本人观测确认同一请求下的有效回信，最后执行现有 `lock_signal` |

**交流与解法。** B 说明发出新挑战，A 收到授权形状或等价字幕并告诉对方自己要回送，例「长、短」。主持人检验回应与服务器所建请求对应，而非看见熟悉波形就确认。B 检验这一轮的回读后锁定。未来挑战绑定存档和当前有效光学配置。换角、光型或滤镜使旧回读失效，可恢复配置并发新挑战。发送与回应异步，玩家无需在精确秒数内点按。两人都可以暂停并从当前请求继续。

**世界与结束。** 现有 B 锁信号在真实光学和双方发现记录的前置满足时进入 `repair`，无请求和回信机关。未来 `echo_signature_verified` 为附加锁定前置。锁定提交后用两端各自的仪表由散到定的演出配现有公共锁定音，公共台词「另一端刚刚回应了你们」。开放 L04。提示先看当前请求图形，再核对自己的回应规则，最后提示只确认本轮回读，无提示自动填写答案。

### L04 · 电流逆行（10 分钟）

**事件。** 未来站点第一次能把电送回从前。旧塔钟箱亮起后，两人还要让初次升起的电流足以稳定走钟。

| 角色 | 场景、可观察物和本人动作 |
| --- | --- |
| A | 钟盖、铆钉和机械刻度近景。通电前只见暗盖。通电后点击齿轮盖执行 `inspect(clock_gears)`，得到现有 `a_clock_gears`。未来以刻度上的擦痕比对静止标位，选「复位刻度」并对接齿轮 |
| B | 斜视路由台与窗，自己的去向与可用扫描能见。用 `route_power(tower)` 给旧塔供电。未来只读本人负载针的短抖或平稳状态，按搭档描述在「直送／稳流」中确认一个模式 |

**交流与解法。** B 先路由，A 看盖板点亮才打开。A 对照齿轮擦痕与正常静止线推断应该静止复位，读出「指针抖动」或「平稳」。B 自己的负载针在直送有短抖，选稳流验证。A 等读数稳定后复位，并反馈齿轮能否落在基线。错模式或错刻度显示有电但仪表不同步，可复试而不损设备。先保持线路，避免边试边改变对方条件。

**世界与结束。** 现有 `clock_powered` 和齿轮检查足以表现 B→A 通电，不提供稳流或对接。未来双方已完成且当前仍给塔供电时产生有效的 `clock_calibrated`，首次里程碑带入 L05，仍在 `repair`。若断电，已发现工具仍保留，当前检修入口暂时停用，恢复同一确认配置可继续。A 的光晕与 B 的负载针分别出现，NPC 对 A「看到盖板亮了，再打开」，对 B「先看你自己的负载针」。提示指向钟盖、建议报抖动、提醒保持已确认供电。

### L05 · 潮汐档案（11 分钟）

**事件。** 时钟恢复后，新扫描出现缺口。两人的记录分别能排除不同的危险时窗，合作把可用检查窗口留下来。

| 角色 | 场景、可观察物和本人动作 |
| --- | --- |
| A | 暖光齿轮和纸质潮刻，已看齿轮且有电时，用现有 `repair_clock(steady)`。未来本人潮刻排除晚段浅滩，保留早段和中段。未来在潮刻拨盘提交自己的可用范围 |
| B | 冷屏扫描台，航路形状随维修及供电确认显现。未来做有区分能力的双段扫描，以岸边标尺排除早段逆浪，保留中段和晚段。提交自己的扫描证据后才调用现有 `confirm_route` |

**交流与解法。** A 告诉 B 晚段不适合检查的理由，B 说明早段逆浪的观测，结合两张证据得到中段。B 在该段用扫描图复核一次能否连续跟踪航路，A 确认这一段确实与本人潮刻一致。这里的时窗是验证参照，不选择实际结局或引入现实钟表。若一方把「看不清」当成危险，提示先让观测满足供电与修复条件。若二人范围不交叠，保留上一个有效证据，可以补测，不倒回前几章。

**世界与结束。** 现有 A 修复和供电使 B 的扫描就绪。B 确认航道后进入 `decision`，时窗核对属于未来 `tide_window_verified` 门槛。掉电暂时关闭扫描和新确认，已修复事实不丢失。A 看到时钟走动，B 看到连续扫描线，台词「我们核对的是能走的路，何时走还由你们决定」。L06 只在 `route_confirmed` 和 `decision` 确认后开启。提示依次读本人刻度、交换各自排除的范围、用获准范围核对中段的验证条件。

### L06 · 抵岸时间（11 分钟）

**事件。** 路已确认。现在点灯能让船早些找到信号，等待能在更从容的海况里引航，两条路径均可完成。A 说出自己守着这盏灯的理由，B 说出对当前观测的判断。

| 角色 | 场景、可观察物和本人动作 |
| --- | --- |
| A | 海窗边暖灯、值班册和私人夹页。未来可以看两种安排各自的静态灯光预览，选择时由本人提交 `vote_ending`。夹页可留作本人阅读，记事不会发送给 B |
| B | 冷台前航路与风浪预览。未来可并排看两种安排的公共后果摘要，用现有 `vote_ending` 提交自己选择。公共事件只提示选择已更新，选择值不从同一历史事件推断 |

**交流与解法。** 两人先各读一条和本角色观察有关的代价或收益，说出选择理由，再各自决定。分歧可改选。翻看预览属于只读，打开哪一张都不会隐性投票。此章的合作价值是以不同观测讨论不可替对方决定的取舍，关掉 NPC 也可完成。未来不设必须重复确认或等待出海的时长门槛。

**世界与结束。** 两票一致才产生现有结局。 `guide_now` 时 A 见船靠岸，B 得公共抵岸记录。 `wait_tide` 时 A 守着灯，B 值班记录只说明继续守候，画面不宣称船已靠岸。两端分别展示对应授权静帧、公共固定台词和回顾，可跳过演出。没有下一章，退出后可回看。若意见不同，用「两种安排各保护什么？」、「请搭档讲出最看重的后果」、「两边一致前可改选」三级作者提示，无标准答案。

## 3. 《末班星轨》六章

站台记录员 A 守着即将从时刻表消失的旧站，列车驾驶员 B 在断轨外保有最后一份现场读数。谜题围绕能源配置、测量误差与机械对位。两人要判断在哪一阶段需要声呐，在哪一阶段需要动力，以及收到灯号后还能怎样核实，而灯塔篇主要检验光学因果与跨时证据。

### S01 · 末班待接（8 分钟）

**事件。** A 找到未盖「已接」的旧车票，B 发现车载表的最后一班看起来比站台日志晚一班。两端必须区分演练记录和仍待接的实际列车，避免为错误班次开闸。

| 角色 | 场景、可观察物和本人动作 |
| --- | --- |
| A | 橙色站灯、滴雨售票窗、无字票面和上锁检修本。用现有 `inspect(station_log)` 取得 `a_station_log`，只有本人拥有闸方向与灯号对照。新增票章卡显示「上一行是演练，下一行实车待接」 |
| B | 驾驶室蓝黑风挡，左手功率板、右手停驶记录。用现有 `inspect(power_board)` 取得 `b_power_board` 和预算。新增记录卡显示「最后一行实际出库，车载时钟未同步」，只能确认实际车，不能确认站台是否已接 |

**交流与解法。** 以实际出库和空接车章为根据对齐班次，口头说明时钟分歧为何不等于两趟车。未来 A 提交「实际班待接」并解释空章，B 标记「实际出库记录」而非车载时刻。仅两端正确才对齐。错选演练行时保持原投影，提供本人记录性质提示，可改选。没有要求输入对方的秘密代码。

**世界与结束。** 现有两次 `inspect` 各自解锁本人控制，未来 `service_record_matched` 才带入 S02。底层仍为 `survey`。开场字幕「回声未确认」，对齐后公共短句「末班仍在等待本站接车」，没有远程乘客状态。提示分别标出票章和出库条目，再请对方说明记录性质，最后针对本人说明实车的判断依据。

### S02 · 把回声送出去（10 分钟）

**事件。** 有班次还需要找到能传回信号的通道。放大一切只会把候车厅的反射当轨道，能源也不足以维持所有装置。

| 角色 | 场景、可观察物和本人动作 |
| --- | --- |
| A | 低机位湿站台，右侧闸杆，左后方候车厅金属挡板。按检修记录把现有 `set_echo_gate` 调到 `east`。新增「吸声挡片」使可辨识响应来自轨道，A 可观察机械标记和候车厅反响的差别 |
| B | 前景电源组和声呐扫线。现有 `allocate_power` 选择声呐开、引擎关，灯可按需要保留在预算内。新增可读声呐轮廓，显示宽散回声或轨道窄峰，B 需根据本人读数保存可用回声样本 |

**交流与解法。** A 打开东闸，B 配置勘测模式并说明是否有稳定窄峰。A 改变挡片，保持闸位，B 比较可辨度而非响度。可用的回声必须能区分轨道响应与房间反射。引擎 3、声呐 3、灯 1，总预算 5。引擎和声呐同开全组拒绝，保持原配置。声音有形状和文字替代，测试靠已确认状态，无需同时按键。

**世界与结束。** 现有东闸、声呐开和引擎关使 B 出现 `echo_available`。校核回声归属、保存样本需新增 `echo_profile_verified`。首次获得时开启 S03，仍为 `survey`。闸门机械声只给 A，B 可看到现有扩散波并读字幕。作者台词「听见回声以后，还要辨清它沿哪里返回」。提示先找本人工具，再交流闸位和窄峰，最后只指向本人可解除的预算冲突或反射条件。

### S03 · 断轨定位（10 分钟）

**事件。** 第一次新探测圈定两个可能缺口，错装会把导轨送到空处。两人以站台和车端两个参照校核，才知道应安装哪一段。

| 角色 | 场景、可观察物和本人动作 |
| --- | --- |
| A | 站台边湿轨枕与前后两枚测量标钉。新增维修图说明桥侧标钉属于有效远端参考，候车厅钉有变形误差。选正确远端参照并报给 B。最终从获准的定位标记执行现有 `install_rail(bridge_2)` |
| B | 挡风玻璃下声呐屏，近测落在 1 或 2 号桥段范围，新增经 A 标记的远测落在 2 或 3 号。以受权样本核对交集，再执行现有 `scan_track` 发布实际定位。未确认时 B 只见自己的候选测量，A 不会看到内部样本列表 |

**交流与解法。** B 说明为什么第一次近测还不能施工，A 选择物理基准。B 按该基准取远测，在确认两份有效样本的一致段后发布定位。A 看见真正可装的桥段再从锁扣完成安装。未来两次探测有不同测量目的。相同样本不会增加证据量，错误参照读数标为「复核不成立」，可重选。

**世界与结束。** 1.0.0 的 B `scan_track` 一次就公开定位 `bridge_2`，无候选或双点规则。未来先满足 `track_reference_verified` 再执行同一终扫，维持定位结果的原有含义。A 安装使 `rail_installed`，迁入 `boarding` 时开启 S04。双方会看到接轨的授权效果，闸锁定。提示从候选区读数、请搭档核对标钉，再到选中双方可支持的区间。报站员「还差一份现场确认，再安装」。

### S04 · 双闪不是到站（10 分钟）

**事件。** 导轨已经接通，需要从听回声切换为看灯号。收到灯号只确认出站信号，站台还要识别是哪个接车位置。

| 角色 | 场景、可观察物和本人动作 |
| --- | --- |
| A | 暖光月台侧看新导轨，眼前有灯号对照本和一盏存在雨滴反射的接车灯。等待信号公开后再查本人对照。新增可检查的遮光片区分湿玻璃的一闪反射与有间隔的两道刻痕，标记本站位置证据 |
| B | 蓝光驾驶台和近景灯号罩。用 `allocate_power` 切为引擎与灯开、声呐关（4／5）。本人见实际蓝色双闪和节奏文本，再用 `confirm_signal` 提交，信号才向 A 公开 |

**交流与解法。** B 说明运行模式已变，先报本人看到的节奏而非轨号并完成确认。A 取得获准的信号后，核对自己保存的记录和反射物来源，以标记的两道刻痕判读该用二号轨。未来检查错误时反馈「这是湿玻璃的反光」，不因答错改轨。A 的私有对照给 B 的唯一可传方式仍是本人主动交流或分享。没有颜色或听力要求。

**世界与结束。** 现有 `signal_confirmed` 使 A 能对位。未来 A 的 `station_signal_crosschecked` 才开放 S05，并作为新对位门槛。底层仍为 `boarding`。B 确认之前，A 仅见等待文本与环境光，没有双闪动画。确认后 A 获公共信号字幕，B 有现有确认音。三级提示为读灯罩或记录、互报节奏、复查对照本中的本人标记。报站员「信号已核实，接车位置由站台确认」。

### S05 · 让列车认出站台（11 分钟）

**事件。** 列车靠近前需要同时确认轨道锁住、车端能源就绪。站台看到实际机械间隙，驾驶室看到来自站台的就绪回馈。

| 角色 | 场景、可观察物和本人动作 |
| --- | --- |
| A | 橙光湿轨的低机位，近景机械锁扣与分道杆。现有 `set_platform(track_2)` 选择对应位置。未来检查轮缘间隙，在机械标记对正时执行锁定，给 B 可授权的「站台已锁」信号 |
| B | 驾驶室风挡中的灯线上移。读本人的发动机和信号状态，未来核对挡位及许可回读并确认接近检查。只有获得合格配置、已确认信号、正轨与新增安全证据才执行现有 `dispatch_train` |

**交流与解法。** A 说清「对准」与「锁住」两个不同条件，B 确认自己有动力且收到站台已锁反馈再推进。现有选择错轨的尝试不能接车，可切回后二次验证。未来调轨会清除安全锁和车端就绪，功率不合格时保持场景但最新就绪失效。没有实时制动操作或新驾驶模拟。停下后恢复有效锁与配置即可，不要求同一毫秒按键。

**世界与结束。** 现有 `dispatch_train` 受原轨道、灯号和能源限制，成功后设置 `train_dispatched` 并进入 `decision`。未来 `platform_alignment_locked` 与 `approach_check_ready` 为附加前置。接车确认后两端播放可跳的进站演出，A 看车头雨光，B 看站台灯接近。报站员「本站已接车」，进入 S06。若轨错、失锁或能源变化，提示从各看本人指示到确认站台回馈，最后只指出本角色可复核的条件。

### S06 · 最后一站（11 分钟）

**事件。** 终于接到末班车，站台要把这一班记在哪里。绕行可以带上支线仍在等待的人，直接归站让这趟已完成的接车安全结束。

| 角色 | 场景、可观察物和本人动作 |
| --- | --- |
| A | 台边暖灯、停稳轮廓与旧票。新增只读卡用公开信息对照「谁会等到车」和「本站已经接到谁」，由 A 表达值班取舍并用 `vote_ending` 表态 |
| B | 驾驶室近景，两条去向由挡风玻璃外的不同引导线表现。新增只读卡解释继续支线和收车归站的故事后果，B 选择并用 `vote_ending` 表态。两条路都不重新扣功率 |

**交流与解法。** 一人说为什么要继续寻找等待者，另一人说为什么可结束本次接车，再互换视角复述对方关心的后果。选择可改，预览只用于理解，无自动投票。玩家可以快速达成一致。时长依赖真实讨论与可读的后果对照，无补时锁。已完成的档只读回顾。

**世界与结束。** `rescue_detour` 显示列车转往支线、候车灯依次亮起。 `return_station` 显示主线归站，A 的车票只标记已接，不暗示支线也完成。保留已有两票同意规则和公开里程碑，无下一章。播「本站有人回应」，字幕可读、画面可跳。分歧时先看后果卡，再询问对方的取舍，最后提示可以改选且无唯一正确路线。

### 建议的状态和恢复规则

- **扩展版单独发布。** 新证据需要规则引擎、动作 Schema 和报错映射、投影评审，并封存在新的内容版本。原有结局、角色归属、既有动作的基本前置和结果保持成立。旧档按照原版本继续，不在读取时套上扩展版新门槛。当前不决定版本号或迁移格式。
- **把已到达的章与当下可用性分开。** 章节里程碑只向前。校准条件、锁扣和接车配置是即时资格。条件改变时只收起相应动作或提示重核，当下章、已发现证据和已完成的原始事实仍可读。按依赖计算可用性，不因无关的分享、阅读或聊天改变设备资格。
- **候选与证据均由服务端确定。** 所有样本绑定存档、剧本版本、角色、采样类型及相关设备状态，去重按样本和依赖范围。L02 的同角度对照用于判断清晰度，L03 改光学配置使该轮挑战失效且可新建。L04/L05 断电禁用当下检查，恢复有效供电与设备设置后仍可用合法读数确认。星轨在终扫前改变闸位、挡片、有效测量参考或勘测配置时复核相关样本，已经确认并公开的原定位不回滚。S05 改轨清除相应锁定与接近确认，功率不合格则暂停 B 的就绪，恢复后只要求重核失效部分。
- **互锁以角色证据代替实时操作。** 举例说，A 锁轨后 B 才去验证许可。版本冲突重新读本人快照，再确认或查询原回执。两个请求的先后由现有 CAS 决定，重复与恢复不产生第二份证明。若观测卡与服务器状态冲突，以确认状态为准。扩展版需要基于有效状态恢复主持人所用的新证据，当前没有相应存储契约。

- **手机竖屏**采用 4:5 主场景和 1–3 个上下文热点，底部安全区放可折叠信息抽屉。各章上述对白位置以场景下缘短条为主。主动操作打开底部设备抽屉，保持核心读数可见。无法同时布局的热点由等价文字列表替代。同一时刻仅打开一个操作抽屉，键盘弹起仍可关闭或确认。
- **电脑**采用 16:9 场景和侧栏设备控件，左上有章节与需要时的同步提示，公共或私密记录分开展开。高亮每章的视觉焦点，小热点可用 Tab 和文字列表访问。平板据宽度选择底部或侧边布局。点击目标至少 44×44 CSS px，焦点可见，Esc 关闭并回到触发点。静音用字幕、颜色变化用文字和形状，减动态用确认静帧。关键文字的对比度目标至少 4.5:1。
- **提交与失败**。打开控件或改草稿不写入。只保留 Game Store 现有的会话、可用动作、预期版本、请求 ID 与参数校验入口。失联或结果未知时保留安全的待确认状态，并按原流程查询原回执或获准重试，期间不播放成功音、不给错误结果。状态确认后才切章。新文案用当前角色已获准读数表述具体条件，拒绝事件不得写入候选证明。
- **提示与合作等待**。每章提供作者编写的三级按钮。如果前台、在线、可行动且有效进度约 60–90 秒未推进，或两次不同的有意义试验收到规则拒绝，仅呈现可选择提示。隐藏、技术等待、播放中、来回试相同行动不累计。低级指物品，中级提示交流，高级引用本人已发现证据。载入后不补发积压，提示不增加存档事实，也无对方的秘密。
- **演出、恢复与资源**。目前有相邻确认快照触发动效和受保护媒体。扩展版允许合法角色读取新 cue，但首帧、连回、跨版本只呈现确认画面和获准文本。已确认的章节可回看，跳过演出和字幕不会触发命令。账号、角色或存档改变时停旧音效、取消读取并清理旧 Blob。媒体或 NPC 失败时，当前角色仍可用合法观察、文本及实际规则操作。AI 模式、许可和隐私沿用既有边界。

## 10. 开发拆分与验收

### 候选执行顺序

1. **纸面走读与证据表评审。** 先用两份角色卡逐章验证真实合作、失效路径、信息可见及节奏，优先打磨 L02–L05、S02–S05 这两条核心循环。记录不足时长的具体节点，调整有效证据或分配，等待人工批准后进入工程。
2. **版本化规则和投影。** 先做章节派生、存档证据与有效条件，再按灯塔对照/回信/检修/时窗、星轨反射/测量/灯号/双检分阶段实施。每次把原版和新版本分别跑通。安全、状态与授权验证优先于正式资产。
3. **前端操作原型与占位图层。** 复用真实命令/快照，先用假素材验证每篇至少一章跨端因果、关键热点及三端可用性，再贯通两篇。完成交互、状态验证与候选提示后，锁定全部锚点和裁切。
4. **正式图层、叙事、音轨与发布。** 按热点表及 T17.3.1 的分角色色调制作、授权和封存。先交母版、透明机关层与静帧，再交字幕、短演出和可选配音。新内容审核通过后才公开，原有测试素材仍单独标识。
5. **新版本真人验收及可选 AI。** 原型先可在无 AI 条件下判断时长和通过情况。模型润色、更多提示表达、私聊或语音分别按授权管理。保留未满足的质量门槛和无滞留降级结果。

### 可执行检查

| 验收 | 操作和通过标准 |
| --- | --- |
| 文档完整性 | 每篇六章且 A/B 皆有独立任务，四类时间各可归类。逐项核对热点唯一性、事件引用、场景、角色、现有动作和媒体，新增标识要显式标为待开发。高保真素材与在线功能等后续成果不给通过标记 |
| 现有基线 | 灯塔依次读册与海图、90° 脉冲与琥珀、B 锁定、B 送电、A 查齿轮并稳定修钟、B 确认航道、双方一致投票。星轨依次读日志与功率板、A 东闸、B 声呐开且引擎关、B 实扫、A 安装 `bridge_2`、B 动力和灯开且声呐关并确认、A 二号轨、B 接车、双方一致投票。各走两个结局，错角色、失电、超预算和错轨验证不产生成功事实 |
| 扩展规则与双端 | 用两套独立角色会话，分别试正确、失败及恢复。代表性失败包括 L03 先发挑战后换滤镜，恢复合法配置并发新挑战才可锁定。S03 错参照和重复采样不能公布结果，S05 改轨使接车安全证据失效。每条新证据拒绝单角色、跨档、冒充旧回读及不授权的查阅。不能通过删减 1.0.0 的原有测试解锁 |
| 暂停与异常 | 第三章中途退出后恢复当前确认状态。再模拟会话切换、断线、动作回应丢失、重复请求和版本冲突。无重复高光和声音，无已确定结局被覆盖。媒体失败用授权文字继续，静音、减动态和坏画面均可通关 |
| 信息与设备 | 比对 A/B 的 HTTP/WS、DOM、媒体请求及 NPC 模型输入。未经本人授权的图层、灯号、日志、样本和私聊对方均不可见。至少验证手机竖屏、平板、电脑，分别记录模拟与 iOS/Android 真机结果。焦点、字幕、替代操作和权限错误都有显示 |
| 效果与时长 | 每篇至少 3 对未看过答案的获准玩家，分别记录各章有效时间、等待、提示级别和双方操作。目标中位 55–65 分钟，常见 50–70 分钟，每章约 8–12 分钟为调试目标。终止后双方各复述一次搭档造成的可观察变化及共同结局的理由。验证是否曾靠直接报答案跳过实际步骤。先如实报告样本与分布，再决定是否达标 |
