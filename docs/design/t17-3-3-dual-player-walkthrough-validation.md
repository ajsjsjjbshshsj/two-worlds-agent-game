## 1. 基线、范围与结论

以 GitHub 默认开发分支 `codex/bootstrap` 的 `9e57dfc24dead948ebb848c4c98b2fd14ab49676` 为基线。已核实 [PR #61](https://github.com/ajsjsjjbshshsj/two-worlds-agent-game/pull/61) 合并，工作分支同时包含合并提交与该 PR 最终提交。以 [T17.3.2 双人纸面原型](t17-3-2-dual-player-paper-prototype.md) 为剧本，按 [产品流程](../01-产品需求与用户流程.md)、[玩法规格](../02-玩法系统与首批剧本.md)、[技术契约](../03-技术架构与数据接口.md)、[测试与验收](../05-测试验收与交付标准.md) 对照判断。

### 走读记法和中断复盘

- 每章流程表中 **实** 表示 1.0.0 能执行的动作；**拟** 表示 T17.3.2 纸面；**建议** 表示处理原型未定义分支。本章拟增加的门槛仅在未来版本成立。
- **A 单人** 同时试 A 账号两会话、B 账号两会话，再检查一人持两合法账号。各章写出原角色被卡在哪里。一人持双角色都能代演表中两端，本章的证据约束将限制盲跳，无法验证谁在输入。
- **D 退出** 各章以最近已提交动作作为断点。A 先走或 B 先走时，另一侧只执行当前有权的独立准备；双方退出后，先回来者读个人快照，晚回来者追到同一权威版本，并继续未完成的工作。恢复取服务端已提交结果。没收到提交回执时查原 `request_id`，不靠版本增长猜成功。补偿快照恢复静态画面而不重播已发生演出。表中单独标注章级草稿、样本或许可的缺口，纸面 D 均是分支演算。
- **C 错误** 每章覆盖相关的参数、顺序、证据与配置；无电力或短期证据机制的章按“不适用”记录。1.0.0 的失败原子性、版本冲突和角色拒绝由基线测试佐证，未来反馈是建议台词。
- 评分以实际写出的纸面分支为依据。5 表示在演算中有强证据，4 为明确有效但有局部弱点，3 为有效但容易代演或偏短，2 为原型存在明显缺口，1 为核心机制不成立或欠缺可恢复定义。评分不代表可运行水平。

## 2. 《跨时灯塔》六章

### L01 · 风暴来信

**独立视角。** A 在旧塔窗下查维护册，能听出海面「三短、停、一长」，无未来档案，无法确定这是否与 B 看到的旧记录同源。B 在未来台查海图，能看到相同节拍的陆侧试灯和海上求援两个索引，无现场方向，独自按节拍无法排除演习。

> A「三下很近，停了才听到长的，声是从海面那边来的。」B「这里有同节拍的演习，但来自岸上测试机。你能确定是海上吗？」A「能，我对着窗标一下方向。」B「那我用海上求援条目验，档案里还没有抵岸记录。」

| 当前状态 | 角色、操作、前置 | 反馈与下一步 |
| --- | --- | --- |
| `calibration` 未查记录 | A `inspect(maintenance_log)`，B `inspect(sea_chart)`，各查本地物件（实，可并行） | 各自发现线索和本端设备；按角色打开拟议转录和索引 |
| 各自观察已读 | A 标记海面来源（拟，须来自本端转录） | A 见本地提交；等待 B 的索引核对 |
| A 来源已提交 | B 核对海上求援而非陆侧试灯（拟，同次事件） | 形成 `mayday_matched`，两端只见公共匹配结果，各自保留原卡；进入 L02 |

**完成。** 此走法由 B 完成核对，A 的来源与 B 的档案是两个证据。1.0.0 只有记录发现，没有章末匹配或单独的庆祝事件。

| 检查 | 结果 |
| --- | --- |
| A 单人 | A 查不到 B 的专属海图，B 取不到旧塔观察；各开两设备仍卡。持两账号可照卡演。 |
| B 报答案 | 「选海面」可省辨识理由。1.0.0 仍需两边查记录；纸面应校验打开的来源和索引 ID，只有固定下拉项可被猜中（L-P1-01）。 |
| C 错误 | B 误选同节拍演习，拟反馈「节拍一致，来源不符」，A 转录保留，B 可改。提前核回应等待对端证据；供电不适用。 |
| D 退出 | A 查完退出，B 可先查索引；B 先查后走，A 可保留来源；两边断点为本人已发现记录。拟议未匹配的来源提交需可读，匹配成功回到 L02 不重播。 |
| E 参与 | 双方最初均可行动；点出陆侧误导时 B 有判断价值。若直接照卡填，先完成者只等确认。 |

### L02 · 第一次试灯

**独立视角。** A 能试发射架角度和光型，从本人记录了解参数含义，只见窗前散光，看不到 B 的地标落点。B 有海图、滤镜和实际光斑，能找相对于目标的偏差，无法替 A 转动发射器。知道配置的 A 或 B 能口述正确值，但不能独立获得同样观测并配置两个设备。

> A「先别换片，我在 180° 把常亮改成脉冲。」B「透明片下还是散的。我换琥珀，你先别动角度。清楚了，落在礁岸，偏离航道。」A「那我转到 90°，其他不动。」B「现在落在航道地标。先把刚才的同角对照留好。」

| 当前状态 | 角色、操作、前置 | 反馈与下一步 |
| --- | --- | --- |
| L01 匹配（拟），两人已查记录 | A 在 180° 试常亮/脉冲，B 保持透明（实）；记第一段对照（拟） | B 仍见散光；可在保持角度和脉冲时换片 |
| 180° 脉冲、透明 | B `set_filter(amber)`（实），B 标记读数且 A 确认保持角度（拟，见 L-P1-02） | B 光斑变清但偏航；只向 A 传口头地标和授权对照状态 |
| 同角试验完成 | A `set_emitter(90, pulse)`（实，参数示意），B 看航道落点 | 拟 `beam_contrast_confirmed` 加当前就绪进入 L03，`lock_signal` 留到下一章 |

**完成。** 正常走法 A 最后对准，B 的滤镜和同角读数给出方向；B 见清晰地标，A 见自身刻度与拟议公共就绪。1.0.0 仍处 `calibration`，达到配置可直接锁。

| 检查 | 结果 |
| --- | --- |
| A 单人 | A 缺 B 滤镜/投影；B 缺 A 发射器。双账号可照做。 |
| B 报答案 | 1.0.0 可直接设置 90°、脉冲、琥珀，跳过对照。纸面至少要一对真实同角观测，重复投递同一观测不得算两次。 |
| C 错误 | 透明片散、180° 清而偏；恢复正确配置即可。两次样本间同时换片又转角，拟拒绝作为同角对照，不清除上一次有效对照；供电不适用。 |
| D 退出 | A 设置后走，B 可换片并读；B 离线时 A 可检查刻度但没有落点。两人返回先看真实设备配置，拟保留已认可样本；半组样本只在上下文仍一致时续用。 |
| E 参与 | A 掌控变量，B 掌控观测，两边都有判断；B 换片时若 A 无法标记自己的参照，容易退化为等待（L-P1-02）。 |

### L03 · 信号锁定

**独立视角。** A 看到授权请求形状与本人的逆序规则，能推回信，无法建立新请求或自己锁定。B 能选挑战、比较当前波形、锁信号，不具备 A 的角色提交能力；只拿旧记录无法确认另一端应答的是本轮。

> B「这一轮我发短、长。先别用之前档案里的回声。」A「收到，短在前。按旧塔的记号要倒过来，我现在回长、短。」B「这条回应挂在我刚发的请求下面，波形也对。我现在锁定。」

| 当前状态 | 角色、操作、前置 | 反馈与下一步 |
| --- | --- | --- |
| 光路就绪 | B 发送短、长请求（拟，仅本人有权，绑定当前光学） | A 读到当前请求形状/字幕，可准备回复 |
| 请求有效 | A 回长、短（拟，引用本轮） | B 获当前回读，A 获本端响应回执 |
| 有对应回读 | B 验证（拟），再 `lock_signal`（实；未来附有效签名门槛） | B 完成锁定；双方见锁定，各切本人检修场景，开始 L04 |

**完成。** B 最后锁。A 必须回应活请求。1.0.0 只检查发现记录和真实光路配置，没有挑战或回读权限状态。

| 检查 | 结果 |
| --- | --- |
| A 单人 | A 发不了挑战和锁定，B 不能以 A 回信；双账号或照通关单可代演，固定两拍逆序易被代算。 |
| B 报答案 | 1.0.0 完全略过回信依然可锁。纸面直接报「长短」可跳过辨认逻辑，仍要 A 在服务器当前轮提交、B 当前轮验证。 |
| C 错误 | A 错回顺序后若先占用唯一回应位、B 又验不过，原型未说明如何在光路不变时重试。若改片再改回，需要拒绝旧轮；见 L-P0-01。供电不适用。 |
| D 退出 | B 发出后退出，A 可读并回复；A 回复后退出，B 应继续当轮验证。双方稍后异步返回可继续有效轮，已换光路则双方见失效而开新轮。原型缺少半轮恢复契约。 |
| E 参与 | A 响应 B 现发的挑战，故事联系强；走熟后可由 B 报答案，且等待期间只有阅读。 |

### L04 · 电流逆行

**独立视角。** A 在塔内看暗盖、通电后查齿轮和静止线，能判断擦痕并复位，不能路由或看未来台负载针。B 看本人路由、针表和可用去向，能送电/拟议稳流，无法看塔内擦痕并对接齿轮。单方可猜一个合理设置，缺另一侧实际读数。

> B「我把电送给塔，你看到钟盖亮了吗？」A「亮了，但针在抖，擦痕不是静止线。」B「我这里直送也跳了一次，我切稳流，你先不扳。」A「静下来，齿轮现在落在刻线了。」

| 当前状态 | 角色、操作、前置 | 反馈与下一步 |
| --- | --- | --- |
| `repair` 未给塔供电 | B `route_power(tower)`（实，已锁信号） | A 见 `clock_powered`；获得检视条件 |
| 塔已供电 | A `inspect(clock_gears)`（实）；B 核对负载并稳流（拟） | A 取得齿轮线索；拟给两端各自读数，可复位 |
| 当前稳流 | A 以静止线对接（拟，电仍入塔且 B 已稳流） | 确认 `clock_calibrated`，A 看对正、B 得校准状态，进入 L05 |

**完成。** A 最后对接。B 的线路与稳流决定 A 能否操作。现有版本只到通电和检查，仍属 `repair`。

| 检查 | 结果 |
| --- | --- |
| A 单人 | A 不能供电，B 不能查/对接 A 的齿轮；两合法账号可代做。 |
| B 报答案 | 「稳流、静止线」可省读表；塔供电和设备可见性仍需真的建立；1.0.0 是通电后的独立检视。 |
| C 错误 | 未供电先开盖失败。拟直送有电但抖动，错位可试。调电至岸上或观测台后恢复塔供电，1.0.0 保留已发现工具；未来锁需暂停，恢复同一有证据配置才续用。 |
| D 退出 | B 送电后离开，A 能检查；A 查完离开，B 可稳流。双方回档取当前供电与已发现齿轮，拟议校准须分已发生里程碑和当前有效配置。 |
| E 参与 | 两人均有关键操作。单改稳流很快，A 可在失电时看静止线做准备，B 可提前核对去向以降低空等。 |

### L05 · 潮汐档案

**独立视角。** A 有齿轮和潮刻，能修钟并依据本人卡排除晚段，不能观察早段逆浪。B 见修钟后的连续扫描，能排除早段和确认路线，不知道 A 的晚段浅滩证据。任一侧只能给一个范围。

> A「钟走起来了。我这张潮刻说晚段会露浅滩，所以早或中。」B「我能看见早段逆浪，只留中或晚。重合是中段，我沿这个窗口再扫一遍。」A「中段和我的刻线一致。它只说明路查清了，出发时机留给下一步选。」

| 当前状态 | 角色、操作、前置 | 反馈与下一步 |
| --- | --- | --- |
| `repair`、齿轮已查有塔电 | A `repair_clock(steady)`（实，未来加校准前置） | A 见走钟，B 得 `route_ready` |
| 钟已修、塔有电 | A 提交 {早,中}（拟，绑定自己潮刻），B 采集 {中,晚}（拟） | 各见自己的证据；可核对同一个观测窗口 |
| 有当前合法的单一交集 | B 复扫中段并验证（拟），A 口头确认（建议，见 L-P0-02） | 授权投影显示“可验证窗口”；B 可确认航路 |
| 当前仍就绪 | B `confirm_route`（实，未来检查当前双证据） | 最后由 B 确认，A 见走钟和公共航路，B 见本人航路确定；进入 `decision` 和 L06 |

**完成。** A 修钟且提供另一份范围，B 用实际扫描与公共结果推进。1.0.0 只检查供电与修复，未引入验证时窗或第三次确认。

| 检查 | 结果 |
| --- | --- |
| A 单人 | A 无扫描及航路确认，B 无修钟和潮刻证据；两个合法账号可按表操作。 |
| B 报答案 | 1.0.0 报「稳修、再确认」即省掉讨论；纸面若两个拨盘可直接填「中」，双方无需排除项。建议服务器评估两个原范围和实扫，拒绝单个正确词代证据。 |
| C 错误 | 过早确认、断电、非稳修均不能推进。拟把无交集/多交集视为未验证，可重采；把看不清当危险应提示先恢复观测。对已修钟和上一次成功里程碑无回滚。 |

| E 参与 | 前半偏 A、后半偏 B；可让 B 先读岸标，A 同时检查潮刻。省去重复点“同意”的无意义停顿。 |

## 3. 《末班星轨》六章

### S01 · 末班待接

**独立视角。** A 在售票窗能查检修本和空的「已接」章，能分演练/待接行，无法证明 B 确是那班实车。B 在驾驶室读功率板与实车出库单，知道时钟未同步，无法判断站台是否已接。两边表上日期/时刻相近不足以单独连线。

### S02 · 把回声送出去

> A「东闸开了，先别增加功率。你现在看见的是单峰，还是一大片？」B「声呐开、引擎关，现在很宽。」A「我只移挡片，把候车厅反射遮掉。」B「窄峰留下了，刚才那片是室内反射。我存这一条。」

### S03 · 断轨定位

**独立视角。** A 从维修图能认出桥侧标钉有效，候车厅有变形，不能读驾驶室的候选值。B 能近测得到 {1,2}，远测只有 A 提供物理参照才可信；不知道车站哪枚钉有误差。A 单独猜二号不能安装，B 单靠近测不能排除一号。

> B「第一圈落在一或二号，我不能直接叫你装二号。」A「靠候车厅的钉歪了，用桥侧这枚，我已经把它标成远端。」B「用那个基准量到二或三号。两张都支持二号，我发布了定位。」A「我看到公开的二号，开始接轨。」

| 当前状态 | 角色、操作、前置 | 反馈与下一步 |
| --- | --- | --- |
| 可勘测 `survey` | B 取近样本、A 查并标记桥侧钉（拟，可并行） | B 得 {1,2}；A 见标记已保存；获得授权的远测入口 |
| 有有效近样本及当前参照 | B 取远样本 {2,3} 并核对交集（拟，当前配置与参照一致） | 共享有效验证状态，原始样本仍仅 B 可见 |

**完成。** A 安装收尾，B 发布定位绑定实际扫描，未来测量依赖 A 的独有标钉信息和真实标记。

| 检查 | 结果 |

### S04 · 双闪不是到站

**独立视角。** A 可读本人站台对照本与遮光材质，能准备区分反光和刻痕，只有 B 确认后才有可用灯号；独自看反光不能判定列车在发什么。B 控能源和灯号确认，灯有电可见本人蓝色双闪，不知道站台私有对照或轨位。

> B「我关了声呐，动力和灯开着，看到有间隔的两闪。灯号我确认了。」A「刚才玻璃自己也反了一下。我遮住它，标尺是两道刻痕。我的对照本把这个节奏指到二号轨。」B「收到，等你现场对位锁好，我再推进。」

| 当前状态 | 角色、操作、前置 | 反馈与下一步 |
| --- | --- | --- |
| `boarding`，导轨接好 | B `allocate_power` 引擎与灯开、声呐关（实）；A 可先翻本站资料（实读投影、拟深化） | 预算 4/5；B 可读实际灯号，A 还不能对位 |

| A 已取得授权信号 | A 遮反光、核对两道刻痕（拟） | `station_signal_crosschecked` 后开放 S05；底层仍是 `boarding` |

**完成。** A 完成复核，合法输入来自 B 确认的信号和本站证据；A 见文字节奏及本人线索，B 只见授权复核状态。

| 检查 | 结果 |

**独立视角。** A 知对照指二号，可设置轨道和拟议锁扣，见间隙是否对齐，无法检查驾驶室电源或发车。B 能核对车端许可、配电与调度，无法实际观察或推动站台锁。单独看到正确轨号不能推断已经锁住且能接车。

> A「轨道对准了，锁扣还没落，我先检查轮缘间隙。」B「我这里动力和灯在，声呐关着，但现在还没有许可。」A「锁落了，二号轨就绪。」B「许可回读到了，我确认接近检查，再发车。」

| 当前状态 | 角色、操作、前置 | 反馈与下一步 |

| 另一票未提交或不一致 | B `vote_ending(rescue_detour)`（实），A 可先选 `return_station` | 保持决策，允许各改本人票 |
| A 改为一致 | A `vote_ending(rescue_detour)`（实） | 双方见结局与各自回顾；绕行表现支线响应，另一结局仅承诺正常归站 |

**完成。** 此走法 A 最后投；B 最后也可，要求两角色票同意。没有额外功率解或唯一正解。

| 检查 | 结果 |
| --- | --- |
| A 单人 | 两设备也只有一张角色票；一人持两账号可操作完整结局，无法以程序验证讨论质量。 |
| B 报答案 | 两人可直接约好结局，仍要两份各自同意。一个人报「绕行」不能单独结算。 |
| C 错误 | 提前投票无效，分歧可改且不扣电；快速重复快照不重复演出，完成后只读。过期样本不适用。 |
| D 退出 | 任一方先投可异步恢复，双方同时退不改变已接受票；先回者只知本人历史和共用结局状态，晚回者可投至一致。完档直接读回顾。 |
| E 参与 | 两边有最后决定权；因果够清楚时会很快同意，11 分钟规划缺足够活动，需实测或把时长留给 S03/S05。 |

## 5. 一小时时间模型

按一对人的墙钟计。两人并行查卡用较长者时间，边读边交流时按本段最主要活动归类一次；更正输入、重新看证据的额外时间列「错试」。网络中断或无事可做的等待单列。演出用可跳过的纸面分镜和短停留估时。模型用半分钟量级区分路径，误差远大于表格小数；未实际连续计时。

- 快速路径为理解卡片、一次确认大部分谜题、尽早达成结局一致。正常路径各中段约一次可恢复错误，结局讨论有来回。较慢路径额外重试 L02/L03、L05 或 S02、S03、S05；均假设修复四个 P0，未把卡死记作有限时间。
- 给技术等待单独注入例子。快速无强制停顿；正常含一次短暂断线、切回和阅读快照；较慢含两次交错回归及一段无事可做的等待。可同时操作或交流的部分已计入相应活动，技术等待只算净时间。
