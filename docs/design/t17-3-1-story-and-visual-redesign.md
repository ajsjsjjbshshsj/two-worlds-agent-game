# T17.3.1 · 双人剧情体验与视觉风格重新设计

设计提案，2026-11-28。基线为 `codex/bootstrap@3c6c92e`（PR #59 已合并）。本文的台词、美术、界面和验收阈值均提请评审。两部剧本的 1.0.0、存档绑定、规则和已发布包沿用当前实现。请先看两部故事和对应的规则，再看分镜与素材清单。故事段落含剧透，书架只使用「公开开场」，玩家页面按角色和阶段逐步揭示。

## 1. 产品体验

TwoWorlds 是给异地情侣及双人朋友的一场约 15 分钟的合作冒险。入场后每个人拥有一处有明确职责的世界。先让玩家知道对方会因自己的行动看到什么变化，再让两人一起决定值得怎样收尾。两个人可以通过自己的电话或当面交流，也可以主动共享已经发现且允许共享的线索。游戏内无玩家实时语音和文字聊天，不依赖关系身份、真实经历或任何付费 AI。

15 分钟从双方进入同一新档、可以开始操作时计时，含阅读、讨论和结局，建房邀请另计。无硬性倒计时、失败扣分或不可恢复错操作。每章让玩家回答「发生了什么、为什么需要搭档、我现在能做什么」。一方暂时无可执行行动时，用本人的观察和已经发生的协作结果承接等待。暂停可以直接离开，返回后从服务端确认的状态继续。

## 2. 《跨时灯塔》· 两次潮汐，一封未寄出的信

### 背景、角色与悬念

**公开开场**

> 一场风暴把同一座灯塔留在两个年代。旧塔听见船的求援，未来站收到一段本该早已消失的灯号。天亮前，海面上还有谁在等这盏灯？

- **A 旧时守灯人**看见黄铜灯架和停住的潮汐钟。值班册里留着一行未填的「抵岸时间」，夹页写着「给下一位守灯人」，窗外的求援船在雾中。A 想给它一条可走的路，却无法看到光束落在哪。
- **B 未来观星者**看见同一海岸的裂窗观测站。观测屏反复收到旧档案中的求援呼号「雨燕」。官方记录在那行「抵岸时间」之前中断，B 起初以为只是旧信号录音，随后发现波形会随对方此刻的操作改变。B 想把记录从「未确认」改成可以亲眼见证的结果。
- **NPC 潮汐记录员**表现为两处机器读出的值班记录。语气克制、留白。当下只复述本人看到的变化与已公开的事实。不会代替两人作出取舍。

### 故事分镜与场景推进

| 时间与场景 | 剧情和 A/B 行动 | 现有触发与反馈 |
| --- | --- | --- |
| 0–2 分 · `calibration` | 开场各用 8–12 秒。A 听见海上三下呼叫，摊开值班册。B 的旧档案末行与当前波形重合，屏上闪出一束模糊的光。A「我能转动灯，但看不见它照到哪。」B「我看得见海面。先告诉我你改了什么。」 | A `inspect(maintenance_log)`，B `inspect(sea_chart)`。本人才能读懂手边记录，开场现有观察与背景 Cue 可作为承载 |
| 2–6 分 · `calibration → repair` | A 试调一道光，B 描述落点和稳定程度。稳定光跟得上此刻的操作，B 确认另一端有人在值班。A 建议按日志分开试验，B 确认内湾信号。锁定后两端各自收到「联络已建立」的公开反馈；A 的夹页仍只在 A 的视角出现，不会自动传给 B。 | A `set_emitter`，B `set_filter`。B 的清晰落点只有在本人读图、脉冲与琥珀条件下可见。双方读过记录、90° 脉冲与琥珀滤镜成立后，仅 B 可 `lock_signal`，进入 `repair` |
| 6–10 分 · `repair` | 未来站原来可以把电送给过去。B 切换供电时，A 从看着黑暗的时钟箱变成能拆开检查。A「你刚才做了什么？这边的齿轮盖亮了。」A 修好后，B 看见噪点让出一条连续的水道。 | B `route_power(tower)` 让 A `inspect(clock_gears)` 后以 `repair_clock(steady)` 修复。维修事实保留。B 转走供电只使扫描暂不可用，恢复后 B `confirm_route` 进入 `decision` |
| 10–13 分 · `decision` | 高潮放在两人讨论。信标足以现在引航，也能保持到海况更从容的时候。A「现在点灯，它就知道我们在。」B「也可以为它留着灯，等风口过去。」两人各自确认。 | 各提交 `vote_ending`，分歧可改选。一致时只结算一次。无可见投票值时显示「共同选择尚未确认」，鼓励彼此说出理由 |
| 13–15 分 · `completed` | `guide_now` 时 A 见船沿灯线靠近，B 的观测屏留下已确认的抵岸标记；未来站的公共值班记录补上一句「收到，我在这里」。`wait_tide` 时 A 看着灯在降下的浪里稳定闪烁，未来站的公共值班记录留下「收到，下一班我来守」，画面停在下一次潮汐将到来之前。两句都是由公开结局 ID 驱动的固定结局叙事，不读取或修改 A 的私人夹页；两人可回读公开回顾。 | 由服务端下发的最终 `public.ending` 选画面。候潮结局不宣称船已经靠岸。回顾只能引用已发生的公开里程碑 |

NPC 短句草案。开场 A「风大时，记下灯转到哪，再请对方报落点。」开场 B「先记你见到的方向。没有看清，可以直接说还看不清。」锁定后两端均可读「这一次，另一端回应了你们的信号。」维修时 A 若有授权的通电观察，可读「现在可以检查齿轮盖。需要的话，先请搭档保持供电。」两名玩家的短句为作者引导或角色卡阅读素材，玩家用自己的话沟通。夹页作为私人分镜的前后呼应，回顾无需加入私人信件。

**规则护栏。** A 无权操作滤镜和路由，B 无权维修时钟。实际行动参数只开放 `steady`。旧稿提到的 `fast` 属拒绝路径，成品控件不提供它。0°、180°、270° 等实际观测是可试验反馈。完整角度表、另一角色日志、未授权的扫描结果留在服务端。新故事的档案、船名、时钟标记和停顿属于内容表现。未来要做可交互耳语、逐句日志或角色专属短旁白，需作者内容、投影和演出契约支持。收尾不增加第三结局或改变现有潮汐规则。

## 3. 《末班星轨》· 最后一班车还认不认得这一站

### 背景、角色与悬念

**公开开场**

> 末班列车停在最后一段断轨外。废弃站台还在上报回声，一张没人收走的车票压在记录本下。把列车接进站之后，你们还要决定最后这段路往哪里开。

- **A 站台记录员**想证明这座站仍然可以接车。站台已从常规时刻表消失，自己保管旧检修记录和灯号对照。只能开闸、接轨、对位，无法扫描线路或开车。
- **B 列车驾驶员**想让末班车先安全进站。他的工作台写着总功率预算，停着的引擎和声呐争夺能源。听到有效回声之前，B 不知道站台和断轨是否真的存在。
- **NPC 末班报站员**是站台和驾驶室共用的一套调度声。句子短而准确，有时会礼貌重复。接车后第一次把两条去向都说完整。对话不承诺有未观测对象，更不替驾驶员操作。

### 故事分镜与场景推进

| 时间与场景 | 剧情和 A/B 行动 | 现有触发与反馈 |
| --- | --- | --- |
| 0–2 分 · `survey` | A 给那张车票盖下「末班待接」的空戳，B 在挡风玻璃上看见一排熄灭的灯。扩音器报「前方站台，回声未确认。」A「这里还有人值班。」B「让我先听见你的站。」 | A `inspect(station_log)`，B `inspect(power_board)`，分别开放本人控制与私线索 |
| 2–6 分 · `survey → boarding` | A 调闸，B 需要停引擎才能给声呐足够能源。声呐实际扫描后，过去模糊的轮廓变成可修的缺轨，A 安装后闸锁闭合。B「我把断点标出来了。」A「收到，接上再叫你发动。」 | A `set_echo_gate(east)`。B `allocate_power` 使声呐开、引擎关，执行 `scan_track`，实际定位 `bridge_2` 才公开。A `install_rail(bridge_2)` 进入 `boarding`。预算 5，引擎 3、声呐 3、灯 1，超预算全组拒绝 |
| 6–11 分 · `boarding → decision` | 从维持静默勘测转为有动力接车。B 的灯先亮出两记蓝闪。B 核实并回报，A 用自己手边的记录辨认对应站台。A 对位以后，B 才能让灯下出现真正的列车影子。 | B 改为引擎和灯开、声呐关，`confirm_signal` 前只有 B 可见灯号。确认后蓝色双闪成为公开事实。A `set_platform(track_2)`。B `dispatch_train`，由规则拒绝错轨或条件不足，成功后进入 `decision` |
| 11–13 分 · `decision` | 高潮从「到不了」切换为「已经接到了，下一站要把谁带上」。报站员「本站已接车。后续方向，请两端确认。」A 关心支线上仍在等待的人，B 可以主张先安全归站。两人讨论已有事实。 | 两人可选 `rescue_detour` 或 `return_station`，各自 `vote_ending`。无倒计时和惩罚，第二票一致才完成 |
| 13–15 分 · `completed` | `rescue_detour` 时 A 看见车尾转入支线，一串候车灯逐次亮起。B 从车窗迎见等候剪影。 `return_station` 时 A 把「已接」印在车票上，B 看见正线尽头亮着归站灯。结尾短句「本站有人回应。」 | 结局 ID 与公开回顾驱动画面。已经完成的接车、选择与里程碑可回看。人物剪影与车票仅是演出 |

NPC 短句草案。勘测 B「预算见你手边的功率板。一次确认一组开关。」定位后两端「缺口已定位，站台端可以接轨。」接车 A 在灯号公开前「先等列车端确认，再翻你的站台记录。」广播不提供轨号对照。蓝色双闪和二号轨只有在规则允许的阶段分别由本人观察、正式确认和 A 的记录关联。

**规则护栏。** A 不能从功率板取值，B 看不到 A 未共享的灯号对照。定位与灯号由现有命令公布，视觉只能使用各自的投影。未扫描不得猜装，接错轨可改，超预算不会擅自断掉另一开关。正式剧情计划的站台广播、车票、乘客剪影与调度短句都是演出，无需加乘客模拟、实时调度或额外耗能。与灯塔相比，这部靠先勘测再切换资源用途的节奏制造紧张，收尾着重于「接谁回家」。灯塔则靠同一动作在两个年代留下痕迹制造亲密感。

## 4. 剧情推进、提示和 AI

### 权威状态如何驱动演出

~~~mermaid
flowchart LR
    P["玩家在本人场景观察或操作"] --> C["已有命令与角色权限校验"]
    C --> S["服务端确认快照与公共里程碑"]
    C --> X["拒绝 · 保留画面并显示本人可理解的原因"]
    S --> A["A 的已授权观察、画面与对白"]
    S --> B["B 的已授权观察、画面与对白"]
    A --> T["两人交流或主动分享已发现线索"]
    B --> T
    T --> P
~~~

- **换章**绑定服务端 `scene_id`，在新场确认时出现一段可跳的短场景介绍。开场作者台词只在本章首次进入时作为引导。读档返回只呈现已确认静态画面及可展开文本。两端因果一致，具体播放时刻可以不同。
- **章内转折**读取获准的 `presentation.visual_state` 和公共里程碑，例如灯塔 A 的时钟通电、星轨 B 刚看到可用回声。已有短演出只对相邻、已确认快照触发。后续角色分镜与叙事字幕也遵循按存档、内容版本、角色、确认版本和事件去重。首帧、重连、跨版本和迟到响应直接收敛到确认画面。关闭声音、后台、跳过时不积压演出。动画或播放完成都不写存档，不作为新场景解锁条件。
- **行为与等待**。热点只呈现当前的个人观察及 `available_actions` 允许的动作。预选只更新本地控制草稿，按原命令契约确认。保留结果待确认、离线和冲突的恢复办法，错误文案提示观察什么，不给无权信息。选择分歧时双方维持本人的选择草稿并可改选，公共通知只写「共同选择已更新」。共享按钮复用 `share_clue`，机制不强制公开。
- **提示**。建议由作者写好的角色与场景提示兜底。进入场景就可主动点「请记录员提示」。同一里程碑约 60–90 秒未推进或两次合法失败时，界面只建议打开提示，不自动朗读、公开或改状态。主动再请求逐级提供「找观察对象 → 邀请搭档验证一种变化 → 用本人已解锁事实提示下一步」，用户无动作也可拿到提示。计时只在前台、在线、无演出阻挡的实际游玩时累积，换章或新的里程碑时重置。读档、离线或后台不补发。失败计数只算明确收到的规则拒绝。灯塔可提示「把变化后的落点说给对方听」。星轨可提示「先问对方是否收到回声，然后检查你手边的功率板」。禁止直接给陌生组合、未公开灯号、搭档的文档和正确结局。现有灯塔内容有三级条目，星轨仅部分场景一级条目，所提分层、授权与入口需开发。

### 现在、必须开发、未来可选

| 策略 | A · 已有能力 | B · 待开发能力 | C · 可选 AI 增强 |

允许的 AI 输入只取服务端当前角色投影、公开事实及本人最近对话。不能给 AI 全局答案表、伙伴私聊、未发现素材、存档原对象或写规则工具。AI 输出只作为带来源标记的私人文本，不得被解析成行动、线索、章节、投票或世界状态。授权变化、迟到、越权内容、模型不可用或预算不足时保持确定性事实和作者提示可用。已经收到普通动作无需重放模型请求。公开回顾来自公开模板。Demo 的固定回复应显示为示例。工件和文案测试覆盖提示注入、跨剧本和 A/B 泄露，真实 Provider 另需授权并验证。

## 5. 视觉方向与两部剧本的分镜

### 方向比较

| 方案 | 适配点 | 成本与风险 |
| --- | --- | --- |
| 半写实电影插画，背景加少量独立图层 | 真实透视、天气和材质提供空间感。可用画面构图分开两个角色，用灯、波形、门和轮廓呈现时序与因果 | 需要先锁定镜头、对象尺寸和光源，避免分层前后风格漂移 |
| 图像小说式平面插画 | 剪影和交互位置容易识别，对屏幕尺寸、素材体积友好。适合回顾卡、章节插页 | 若用作全场默认，容易让海雾、远处船体和驾驶室景深失去叙事作用 |
| 预渲染写实 3D 镜头 | 几何和镜头复用稳定，适合机关精确对位、可从多个角度取景 | 双剧本都需要先做完整资产和灯光。连续 3D 动画的成本与手机压力偏高 |

**推荐**半写实电影插画加 2.5D 分层。把可读性强的图形表达用于灯号、记录和回顾插页。难以对齐的硬表面装置可用简单 3D 作透视底稿。每篇先做 A/B 两张代表性镜头比稿，以手机裁切和机关可辨性作选择，再锁风格。插画媒介和画风可在比稿时调整。

共用构图语法。前景有可交互物，中景表现角色的工作空间，远景交代事件。动态和高亮集中在真正变化的部分。可用热点先用构图、光线、文字与图标暗示。请避免每处可见细节都可点击的假承诺。跨角色可共用公共符号、三拍节奏、同一海岸线的地标或车站编号，A/B 背景各自制作，采用不同镜位、光源与物理空间。设计规范和最终审批见[视听要求](../07-场景动效与音频设计.md)。

**分层和状态一致性。** 背景母版建议 2560×1440，保留约 10% 安全边界。竖屏主场景按 4:5 单独裁切或补画，图层复用同一机位的透视和主体尺度。封面另出 2:3 公共图。在每张母版附相机轴、地平线、主光方向、色卡、物体锚点和许可版本。热点以角色、场景和裁切变体记录归一坐标，桌面和手机分别校对。基底保持稳定，分离动态光、手柄、仪表针、雨雾和遮罩。背景交付 WebP，透明层保留 PNG 母稿并导出透明 WebP。发布与按权限加载继续走现有媒体路由，最小实现先用单张授权背景和少量层。历史或隐藏层不随页面下载。移动端首场必需图片建议合计不超过 1.5 MiB。环境音压缩循环、旁白与字幕按需加载。版本升级不能打断继续读取旧版档。

**来源记录。** 对每个导出件记录 ID、剧本版本、角色/阶段、作者或工具、生成提示词及版本、参考原图的合法使用范围、许可证或书面授权、源文件和发布字节哈希、改图及审核人。图、字型、配音和音乐均逐项审核。声音授权说明能否裁切、循环及商业发布。CI 合成资源保留 test-only 标记。生成素材也要人工审查授权与视觉相似性，通过封存和 Playtest 签核后才能进入相应环境。禁止使用真实玩家肖像、声音或私聊作输入。

## 7. 前端界面重设计

| 界面 | 体验与操作 | 对当前能力的依赖 |
| --- | --- | --- |
| 登录后与房间 | 用安静的开场插画突出「和搭档进入」或「继续故事」。等待时显示房间是否满员与可读故事短介，还可复制邀请。角色称谓可见，回收登录/连接错误到当前入口 | 沿用身份、房间、邀请和存档。不把已加入房间说成实时在线 |
| 剧本书架 | 两张独立封面卡展示故事开场一句话、约 15 分钟、个人角色和开始/继续/回看。回到旧档按绑定版本读取 | 沿用 `Library.vue` 的目录与存档状态。公开封面仍需安全发布引用 |
| 主场景 | 顶部只有回书架、章节名、个人角色及需要时的恢复状态。中央大画幅和 1–3 个上下文相关热点。先显示当前变化、必要对白和一个能理解的目标。画面中不默认展开全量设备 | 依赖已确认角色快照、当前场景背景和可用动作。技术 ID、版本、完整事件表与补偿操作放到需要时的恢复详情 |
| 剧情与 NPC | 本人对白以短字幕或对话条贴近对应观察对象。打开 NPC 面板后显示角色名、问题输入与模式，优先提供作者提示按钮。旁白字幕可收起、扩大或重读，关键事实长期可查 | 专属作者对白及 NPC 面板待开发。纠错、私聊与公开回顾分开，声音关闭时用相同事实文案完成 |
| 线索和个人笔记 | 默认显示当前关联的观察，抽屉收纳已发现线索。主动分享时预览具体条目和公开范围。公开线索独立陈列。首版的「我的笔记」可先以当前已解锁记录组成，可选的自由书写与同步待独立设计 | 私人机制用现有角色投影。不预填对方线索，不自动分享或保存自由文本 |
| 设备操作 | 点击灯架、齿轮或控制台，在原位弹出符合世界观的转盘、拨杆或功率组。显示本人确认读数及待提交草稿，执行按钮只确认当前一组设置。白名单动作对应中文动词，也有可聚焦的文字备用入口 | 重用 `ActionPanel` 的参数验证与 Game Store 提交流程。服务端拒绝时只反馈原因和恢复入口 |
| 章节进度、回顾与结局 | 按已确认场景显示章节名和当前目标。两种去向以等权故事结果呈现。一致完成后以本人静帧、公共结局和公开里程碑收尾。回顾可从书架再次打开 | 复用已确认的 `scene_id`、`public.ending` 和公共回顾。现无逐人投票投影，依靠通用提示与双方交流。如果未来显示准备状态，需以角色权限审阅新的最小服务端字段 |

**手机竖屏**。上半部分保留角色静帧、1–3 个可触及热点及状态，底部是可拉开或折叠的观测、临时操作和记录抽屉。贴不下的热点由可聚焦同义列表代替。键盘弹起时 NPC 输入与提交仍可见。对话不覆盖关键画面。保留安全区、字号放大行为及至少 44×44 CSS 像素点击区。

**平板与桌面**。平板横屏和桌面将场景置于视口中心，抽屉按需变成贴边面板。支持键盘焦点循环、Esc 关闭并回到触发点。不强制全屏。辅助文案对比度目标 4.5:1，开启减少动态时显示静态关键帧。区别通过比例和面板位置体现，文字、图层语言与热点语义保持一致。同一个设备只能看到本人角色及该角色授权的视角。

## 9. 可执行的验收标准

本轮验收是审读与现有契约检查。下表是后续实现的执行清单，指标为建议门槛。按照[验收标准](../05-测试验收与交付标准.md)分别记录领域、浏览器、真机与部署证据。

| 验收面 | 操作与通过标准 |
| --- | --- |
| 两部剧本与四个结局 | 用两个独立浏览器角色以规则轨迹逐一完成四个结局。单角色尝试完成应失败，双方分歧可修改且一致只结算一次。每次场景改变应由已确认状态触发，退出后重进保持原存档和版本 |
| 因果可读性 | 灯塔 A 调光、B 供电、A 修钟、B 复核各抽查一处。星轨 A 开闸、B 定位、A 接轨、B 确认及 A 对位各抽查一处。让搭档描述收到的变化，再从另一端发出下一步。错方向、无电、超预算、错轨与错角色验证失败或可撤销反馈按原规则执行 |
| 权限和隐私 | 比对 HTTP、WS、实际图片和音频请求、DOM、浏览器缓存、公开回顾和 NPC 输入。确认灯塔 B 的未分享落点/航道图未被 A 下载，星轨 B 未确认灯号不出现在 A 的投影，A 的未共享对照、伙伴私聊和未获准媒体无法从另一端读取。共享后只出现获准条目 |
| 全流程体验 | 从房间到书架、封面、场景、提示、结局和回顾走一遍。首屏突出一项主要目标与至多三处相关热点。关键台词有授权静态文本，图片或声音失败后用同一观察继续完成。关闭模型服务时照常完成两剧本 |
| 移动和无障碍 | 先模拟 360×800、768×1024、1440×900，再用实际 iPhone Safari、Android Chrome、平板和桌面验证。检查横竖屏、软键盘及 200% 字号、手指触点、焦点顺序、对比度、减少动态、静音、音频主动开启及媒体失败。记录设备、浏览器和各通道结果 |
| 同步与演出 | 两端并发提交、丢失 HTTP 回执、断线重连以及切档或登出。结果未知时不显示成功。相同或迟到快照不重复播放，跨版本与重连直接呈现最终状态，跳过演出不产生写请求。静态画面不依赖音画播放结束 |
| 视觉与素材 | 逐项用清单核验 53 个基线引用和获批追加件，对照 A/B、两结局分镜及手机裁切。每个可交互物至少有视觉与非颜色标记，光线与机关锚点跨状态一致。媒体从角色授权端成功加载，合成 test-only 内容和正式签核记录明确可区分 |
| 节奏与故事理解 | 获准后，每篇用至少 3 对未了解答案的双人组探索，从双方可操作计时，目标中位 12–18 分钟，所有测试报告样本量。每组结束请两人分别说出一条「搭档怎么改变了我看见的世界」和自己的结局取舍。记录单人卡点、提示使用、章节耗时和无障碍阻断。在小样本中只报告观察结果 |
