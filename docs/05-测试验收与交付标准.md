## 1. 分清交付等级

| 等级 | 必要证据 | 可以怎样描述 |
| --- | --- | --- |
| L0 设计完成 | 文档一致、来源与取舍清楚 | 已有完整设计提案 |
| L1 规则原型 | 纯规则、投影与内容测试 | 游戏规则可在测试中运行 |
| L2 本地可玩演示 | 两浏览器两身份通关、恢复、实际服务启动 | 本地演示可玩；注明数据库和模型模式 |
| L3 首版工程验收 | Mongo 契约、前后端、E2E、配置、文档通过；设备结果明确 | 首版工程范围通过，列出真机/模型等未验证项 |
| L4 三端完整验证 | L3 + iPhone/Android/电脑实际验证通过 | 三端首版通过实测 |
| L5 公开服务 | 实际发布、HTTPS/WSS、备份恢复、运行与内容处理准备 | 指定地址已经上线，标明已知限制 |

L3 若存在核心安全/原子提交失败或核心测试未执行，不算通过；真机暂缺可以交付桌面工程结果，但等级停在 L3。实时通话、在线ASR/TTS、支付等后续范围不作为本版通过条件；场景画面、因果动效、基础音频与字幕属于首版必需，不能笼统以“语音后续”排除。

## 2. 测试分层

| 层 | 数据/工具 | 要验证什么 |
| --- | --- | --- |
| 内容校验 | 两套版本化剧本 | 引用完整、结局可达、私密内容不进目录 |
| 领域规则 | 纯 Python 状态与动作 | 因果、前置、角色、失败不变、无软锁 |
| 投影 | A/B 快照与上下文捕获 | 隐藏信息不泄露，公开回顾正确 |
| 仓储契约 | SQLite 独立连接、真实 Mongo 独立客户端 | 唯一创建、CAS、回执原子、重开恢复 |
| API/WS | 真实应用进程、测试客户端 | 身份、成员、错误、会话过期与实时恢复 |
| AI | demo、可捕获输入的假 Provider | 上下文边界、降级、超时、陈旧版本 |
| 浏览器 | 两个独立 context、窄屏 | 完整流程、切档、重试、版本与缓存 |
| 真机 | 实际 iPhone、Android、桌面 | 安装入口、键盘、前后台、重连 |
| 部署 | 反代、Mongo、持久卷、备份 | 就绪、WSS、故障、恢复和运行手册 |

mock 能验证应用协议，不能证明 Mongo 原子性；浏览器改 viewport 能验证布局，不能证明 iPhone 后台行为；生产 build 成功不能证明用户旅程可用。

## 4. 投影、身份与房间

| ID | 场景 | 明确通过条件 |
| --- | --- | --- |
| QA-P01 | A/B 私密隔离 | HTTP、WS、命令响应、目录及AI输入无伙伴未公开线索/私聊 |
| QA-P02 | 线索发现与分享 | 未发现不能分享；分享只公开指定文本，不附带私人对象 |

| QA-P04 | NPC 本人历史 | A提问不进入B私聊，别档对话不进入当前上下文 |
| QA-I01 | 创建身份 | 密钥和token独立；数据库只存摘要；响应不缓存 |
| QA-I02 | 所有权 | account_id、昵称、伪造token都不能认领身份 |
| QA-I03 | 恢复与跨设备 | 恢复签发新会话，身份与房间/存档保持相同 |
| QA-I04 | 过期与撤销 | 到期、登出、被移出5会话窗口的token在HTTP与WS均失效 |
| QA-I05 | 输入与限频 | 超长/额外身份字段拒绝，恢复接口超额429且不泄露账号 |
| QA-R01 | 双人占位 | 创建者为A，加入者为B，禁止客户端指定角色 |
| QA-R02 | 竞争与重复 | 两人抢B仅一人成功；已加入成员重试不重复占位 |

| QA-R04 | 未满员房间 | 可读开场；游戏写操作与NPC调用被拒绝 |

对网络响应做序列化内容检查，同时验证对象字段；不能只检查 UI 是否隐藏。特意在对方私有内容放入独特测试标记，确认它没有流入任何另一方通道。

## 5. 命令、并发与存档

| ID | 场景 | 明确通过条件 |
| --- | --- | --- |
| QA-C01 | 同版本两动作 | 独立数据库连接竞争，唯一提交；另一请求冲突，未覆盖胜者 |
| QA-C02 | 同请求重试 | 相同actor+ID+内容只产生一次规则效果、版本与回执 |
| QA-C03 | 同ID改内容 | 返回REQUEST_ID_REUSED；状态不变 |
| QA-C04 | 成功响应丢失 | 原请求旧版本重试能确认成功，返回当前快照，不重复推进 |
| QA-C05 | CAS败后回执 | 同一请求并发提交，失败一方重读识别胜者回执而非误报失败 |
| QA-C06 | 512上限 | 新命令显式拒绝；既有回执可确认；读档仍可用 |
| QA-C07 | 本人回执查询 | 仅当前actor可查；未找到不被误解释为“从未执行” |
| QA-S01 | 存档唯一创建 | 两成员并发为同房同剧本建档得到同一Save |
| QA-S02 | 服务/文件重开 | 进程关闭重建后状态、角色、对话、回执仍在 |
| QA-S03 | 数据库失败 | 不返回假成功；恢复后重试最多执行一次 |
| QA-S04 | 剧本与房间隔离 | 不同pair/script的版本、物品、事件、私聊和回执不混用 |
| QA-S05 | 版本绑定 | 发布新版本后旧档仍按旧定义恢复，不静默升级 |

Mongo 必须使用真实数据库执行上述仓储相关用例。建议至少一次双进程测试，排除仅因同一应用锁而“看起来安全”。

## 8. 固定演示脚本

1. 两个干净浏览器 context：甲创建身份保存密钥，乙另建身份。
2. 甲创建房间并把邀请交给乙，乙加入；第三身份尝试读写与加入被拒绝。
3. 进入灯塔，展示A调角度改变B观察；B供电开放A维修，双方完成操作链。
4. 中途刷新A；B继续一次操作；A恢复后显示最新版本。
5. 模拟一次请求成功但响应丢失，使用原请求重试，确认只变化一次。
6. 灯塔尚未结束时切星轨，执行开闸、声呐、功率与导轨操作；切回灯塔仍为原进度。
7. 停止后端再启动，恢复身份与存档；完成灯塔共同选择并查看公开回顾。
8. 完成星轨；A向NPC提问，B看不到A对话；示例模式明确。
9. 窄屏、离线、前台恢复与完成档回看；真实手机按设备表重复关键流程。

演示录像或截图只能证明画面；并发、授权和数据库原子性仍需对应测试记录。
