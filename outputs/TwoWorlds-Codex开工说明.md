## 项目目标

构建面向异地情侣的双人 AI 互动剧本平台 TwoWorlds，支持 iPhone、Android 和电脑。先完成可运行、可测试的最小版本，再迭代语音与商业化。

## 技术约束

- 前端：Vue 3 + TypeScript + PWA。
- 后端：Python 3.12+、FastAPI、LangGraph、MongoDB。
- AI：负责场景补充、NPC 对话与结局润色；正确答案、因果、角色权限和完成条件由纯 Python 规则引擎裁决。
- 实时：WebSocket 首帧鉴权、个人可见快照、心跳、断线重连、版本防回退。
- 持久化：每个房间每个剧本独立存档；Mongo 单文档 CAS + 幂等回执。
- 语音：只预留 LiveKit/WebRTC、ASR/TTS 接口和能力状态，首版不宣称已实现。

## 开发顺序

1. 先检查工作区、AGENTS.md、现有文件和依赖；不要覆盖用户已有改动。
2. 以设计稿阶段 1～5 建立可验收任务，先跑缺失行为测试，再实现。
3. 优先打通“两个身份 → 双人房间 → 灯塔剧本 → 六步合作通关 → 重启恢复”。
4. 再增加第二剧本、独立存档切换、Vue 页面与移动布局。
5. 接通 WS、并发 CAS、重复请求确认、断线恢复与多设备场景。
6. 接通 LangGraph 示例模式和可配置模型 Provider，不擅自发起付费模型调用。
7. 完成容器、Mongo 契约测试、双浏览器 E2E、运行说明和如实测试报告。

## 必须遵守的实现边界

- 身份由服务器凭证确认，不信任前端传来的用户 ID 或角色。
- 所有 HTTP、WS、AI 和语音能力入口执行相同的成员授权。
- 私有线索在服务器投影时裁剪，不靠前端隐藏；AI 只接收当前玩家投影。
- 同一档的状态、版本、幂等回执原子提交；不用进程内锁替代数据库并发控制。
- 相同请求 ID 与不同内容发生冲突时拒绝；网络重试保留原 ID。
- 先识别已接受请求回执，再检查 expected_version，确保丢失响应后仍能确认成功。
- 前端不接受旧版本覆盖新版本，切档不能串入旧请求结果。
- AI 不持有修改游戏状态的工具；生成失败或内容异常不能破坏存档。
- 不把恢复密钥、模型密钥、会话凭证或私聊正文写入普通日志和公开源码。
- API 与认证数据不进入 Service Worker 离线缓存。
- 无法执行的真 Mongo、真机、语音或部署验证，明确写“未验证”，不能宣称通过。
